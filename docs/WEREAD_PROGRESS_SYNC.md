# 微信读书网页进度与阅读时长同步修复

## 协议边界

保留现有网页登录和 `/web/book/read`，不直接套用 Android `/book/read` 的认证、签名及离线时长参数。参考官方网页公开脚本 `wrwebnjlogic/js/9.f252b488.js`（2026-10-18核对）、用户提供的墨水屏客户端反编译，以及本地 KOReader 插件。

网页端的 `rt` 是秒，`ts` 是毫秒；`sg` 使用当前配置 token 计算。请求成功不等于累计时长已记账，必须区分业务应答和服务器回读。

## 顺序与成功判定

1. 进入阅读器、首屏刷新和预绘制空闲后，后台读取 reader 页面取得 `psvts/pclts`，通过 `/web/getConfig` 获取 token，并发送一次不带 `rt` 的 enter。仅在 enter 应答后开始累计可提交的在线阅读时长；不回填 enter 前的时间。配置 token、Cookie 不写入日志。
2. 同一次书籍阅读保持 `Api` 会话对象与 `ps/pc/token`，每60秒提交实际新增的在线活跃时长，退出时处理余量。不能在每次报告前重新 fetch reader/enter。TCP/TLS 连接可关闭释放内存，不清除阅读会话参数。
3. 每次提交前通过 `/web/book/getProgress` 读取累计 `readingTime` 基线；没有可用时长基线时不发送带时长的请求。持久化 InFlight 回执后再 POST。上报专用 HTTP 方法不自动重试、续期后重放非幂等 POST。
4. 明确的 `-2054` 拒绝允许刷新配置并重试一次。其他明确业务拒绝退回 Ready；断线、空对象、未知应答均保持待核验，不自动重复提交同一段秒数。
5. 收到有效 `succ` 或同步游标后记为 Accepted，再回读累计时长和位置。只有位置一致（或接受后云端位置已更新）且累计时长增长不少于本次秒数，才能确认并从队列扣除本次快照。
6. 没有活动阅读会话的后续网络任务不再发送 Ready 历史时长；InFlight/Accepted 可进行一次 GET 核验，不重放。尚未确认的回执和离线/建会话前的秒数进入独立 held 文件，释放活动队列位置，不阻塞新一轮真实在线阅读。held 文件初版仅留存，不自动补发或凭后续阅读增长清账。
7. 断线时使当前会话失效；恢复网络后重新 enter，重建前经过的时间仍是离线/本地时间，不能塞进新会话。一次网络连接内建会话最多尝试3次，失败间隔30秒，避免无限请求。HTTP、位置解析、SD检查点都在后台完成。

这里的回读是可观察的一致性检查，不能严格证明多设备同时阅读时每一秒的来源。服务端最终统计规则仍需实机验证，不宣称已解决服务端风控或已验证任意离线时长补账。

## 阅读位置与百分比

- 不再把本地重排的 `content_position` 直接当作网页 `co`。
- 网络任务从未注入评论的原始章节缓存匹配唯一阅读摘录。已有 `data-wr-co` 时使用显式坐标；原始 XHTML 没有此字段时，使用完整原始 HTML 中的 UTF-16 位置（标签、实体的源码长度都计入）；TXT 使用原始文本 UTF-16 坐标。不能使用本地重排后的字节位置或可见文字计数。
- 官方网页 `utils` 的 `parse()` 在清理 HTML 时以 `sourcePosition`、`indexInFullHtml` 映射回原始 HTML，再给文本添加 `data-wr-co`；该字段不是下载的原始章节必须携带的内容。静态核对来源：[官方公开脚本 utils.9951d3a1.js](https://cdn.weread.qq.com/web/wrwebnjlogic/js/utils.9951d3a1.js)（2026-10-18）。实体解码只用于匹配，坐标仍保留实体源码长度；非 BMP 字符占两个 UTF-16 单位。
- 无显式坐标且缺少 body 的 HTML 片段、EPUB重新封装、短/重复/无法匹配摘录，以及超过512KiB的原始章节，暂不猜测位置，保留待同步记录。日志记录具体 reason、源码/摘录长度和坐标基准，不打印阅读摘录或账号凭证。匹配发生在网络任务，不给翻页增加章节解析。
- 百分比使用目录中的章节字数加权；目录字数不可用时保留服务器已有百分比，不再按章节等权猜测。
- 修正原文摘录源切片，使经过简繁转换的横排文本从当前行对应的原文起点取摘要，而不是整个映射段的起点。

## 多书籍队列与掉电安全

`/sdcard/.reader/weread/progress_<账号VID的十六进制编码>.bin`，格式WRP6。一个账号队列保存多本书的最新位置、尚未同步的实际阅读秒数、记录时间、递增修订号和上报回执。

- 账号在打开阅读器时捕获，不按上传时当前账号猜测归属。
- 同一本书合并真实新增秒数，不同书和账号不覆盖。
- 上报期间出现新的检查点，回执只扣除当次快照，保留新位置和新增秒数。
- 一份检查点可以包含建会话前的5秒与在线60秒；确认60秒后仍保留5秒，不能因修订号相同而删除整条65秒记录。
- 写临时文件，校验关闭后轮换 `.bak` 并提交；从备份恢复时不能确定丢失的主文件是否曾包含 InFlight 回执，因此 Ready 记录转入待核验隔离，不能自动重放。
- 旧 `pending_progress.bin` 缺乏账号归属和可靠坐标，保留原文件，不自动归入当前账号或上传。原本书籍本地 `.pos` 续读记录不删除。
- `progress_<账号VID十六进制>.bin.held` 使用同样的WRP6记录序列，允许同一本书出现多个互不重放的历史检查点。先写held再移走活动记录；两步间掉电最多产生重复的隔离副本，不会令旧秒数重新可提交。旧的199秒回执仍在SD上，没有被删除或假装成功。
- 云端进度时间晚于本地记录，或本地时钟无效，保留记录，不回滚云端。

## 调度与性能

阅读计时仍采用 `esp_timer_get_time()` 单调时钟，不依赖RTC；网络上报签名和跨设备冲突判断使用有效Unix时间。

`ReadingSession` 后台任务拥有全部参数副本，不保留Activity、分页、字体或预绘制缓冲指针。主线程每秒更新短内存快照，无SD/HTTP操作；每60秒及退出时由worker写检查点并结算。实际读时使用单调微秒时钟，菜单/注释弹窗、Activity隐藏、超时闲置不累计；只有网络连通且enter已确认的活跃区间可上报。

worker使用core0、优先级1、8192字节内部栈（NVS/Flash API要求）。空闲时开始请求，结束后释放TLS内存。页面交互不等待worker退出；worker自然处理最后快照并析构全部C++资源后退出，不强删任务。快速切书最多保留两个worker，任务申请失败仍在退出时保留本地记录。网络读请求可能跨越用户下一次点击，需实机验证刷新竞争；低优先级和空闲启动不等于绝对不重叠。

进度事务锁串行化创建检查点、POST、确认/隔离；返回书架的旧同步任务使用try_lock，不抢正在提交的检查点。微信读书HTTP请求串行化，Cookie共享表及NVS账号读写加锁，避免评论/书架任务与阅读心跳同时发起两个TLS事务或修改共享容器。

## 测试

`tools/test_weread_sync.cpp`：业务成功/错误应答、回读不足不确认、章节字数权重、UTF-16与显式坐标、重复摘录拒绝、多书/多账号、未知百分比、并发新增检查点、旧回执不误删新记录、回执重启保留、备份恢复不重放；另验证enter后时间交集、离线区间、微秒取整、199秒隔离后新60秒独立入队、65秒检查点仅确认60秒时保留5秒。

实机流程：

1. 正常联网，打开文字章节，先确认 `reader session enter: accepted=1` 和 `WEREAD_LIVE: session ready`；继续正常阅读2～3分钟并翻页，再返回微信读书目录。原始 XHTML 无需自带 `data-wr-co`。
2. 提供 `session ready`、`reader report`、`report readback`、`live server-confirmed` 或 `live retained`、`progress held` 日志。检查reader enter不是每分钟重复出现；下一次enter只应在重建失效会话或再次打开书籍时出现。
3. `accepted=1 confirmed=0` 只表示请求接受、尚未核验，不能再记成 uploaded。该段进入held，不阻塞后续新会话，也不自动重放；检查手机端累计时间是否在新的实时报告后增长。
4. 手机端核对位置及累计时长；分别测试Wi-Fi、4G。
5. 断网阅读两本书后联网，检查两条队列均保留；上传断线/复位后不得重复POST同一段时长。

本地测试和编译不能代替服务器记账验证。没有使用账号凭据或发送虚构阅读记录。
