# 阅读目录与章节索引内存（当前阶段）

EPUB、MOBI／AZW3、FB2、DOCX、ZIP／CBZ 的常驻目录记录及相应索引容器使用 `metadata_memory` 分配器。ESP 平台显式指定 `MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT`，不回退到内部 SRAM。目录标题、资源路径等长期保存的字符串也使用此分配器，避免只迁移外层 vector/map。短字符串内联于记录内，随记录分配在 PSRAM。

统一重排阅读层的目录／章节表同样显式使用 PSRAM。EPUB 直接移动原解析器的导航表，并释放解析完后不再需要的 manifest 和 href 索引，减少一份完整副本；资源读取继续使用 ZIP 索引。关闭书籍时归还容器容量，不只调用 clear()。

这不表示书籍解析过程的所有临时字符串、正文、资源、微信读书 API 数据都已迁移到专用分配器。正文按现有格式策略处理；目录分页读取尚未实现。

## 临时保护及已知限制

当前 `Budget` 的每类索引条数上限为 16,384，每个检查阶段累计估算上限为 2 MiB；缓存内单字符串限制为 16 KiB。某些格式还保留原有更严格的格式校验。

单条累计成本为 `3 × 结构大小 + 2 × 各字符串长度之和 + 128`。这是为容器扩容／索引开销保留余量的估算，不是实测内存，也不是整本书或整个应用共用的 2 MiB 总预算。预分配还会检查最大连续空闲块；部分增量检查预留 512 KiB PSRAM。它们不能保证所有解析临时分配均不会耗尽内存。

超限当前会返回打开失败，不会截断后继续。此限制是临时保护，会影响大型书籍，后续应替换成 SD 卡完整索引＋PSRAM 目录页缓存；当前尚不支持这种降级。分配器沿用标准容器分配失败语义：无 C++ 异常的固件中，未被前置检查覆盖的真实分配失败仍可能终止程序。
