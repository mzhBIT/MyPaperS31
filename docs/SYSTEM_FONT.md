# 系统 UI 字体

## 使用

设置 → 系统字体（设置列表向上滑动可见）。

- 默认：内置 UI TTF 子集，28 px。参考 pico reader 的约 27～28 px 常规 UI 文字，不是照搬其全部书架布局。
- 字号：24～48 px，每次增减 2 px，立即生效。
- 字体：内置字体，或 SD 卡 `/fonts` 目录下的 TTF / OTF 文件。
- 字体路径与字号存入 NVS `system_font` 命名空间的 `path` / `size` 键；重启保留，恢复默认设置时清除。
- 系统字号与阅读器正文字号独立。位图图标、地图署名小字及触摸校准数字不随系统字号变化。

当前嵌入字体来自 `Assets/pingxianzhensong.ttf`，生成产物约 497 KiB。无需把此源 TTF 放到 SD 卡才能显示常规界面。

## 生成与构建

```powershell
python -m pip install fonttools
python tools/subset_system_font.py
python tools/subset_system_font.py --check
```

换内置字体时指定 `--src path/to/font.ttf`。脚本扫描 `main` 下 C/C++ 字符串，包括英文、简体中文、繁体中文语言表、键盘和运算符；另外保留可打印 ASCII 与常用符号。字符覆盖取决于源字体本身，缺字写入 manifest，不会凭空生成字形。

提交 `main/assets/system-ui.ttf` 和 `system-ui.json`。普通 ESP-IDF 构建直接嵌入已生成文件，不需要 Python fonttools，也不会在每次构建时重裁剪。更新 UI 文案后必须先检查覆盖，需要时再重新生成，具体流程见下文。manifest 记录源文件名、SHA-256、字符数及缺字。

### 界面字符串变更的必检流程

每次新增或修改界面字符串（包括简体中文、繁体中文、英文、提示信息和特殊符号），完成代码修改后必须执行 `python tools/subset_system_font.py --check`，确认内置 TTF 子集是否需要更新，不能只凭肉眼判断或以编译成功代替覆盖检查。

- 检查通过且没有新增未覆盖字符：可以保留原子集，不必重复生成。
- 检查提示新增缺字：执行 `python tools/subset_system_font.py` 重新生成，再执行 `--check` 复查；有变化的 `main/assets/system-ui.ttf` 和 `system-ui.json` 必须随代码一并提交。
- 源字体本身不支持的字符：重新生成不能解决。检查 manifest 的 `missing_codepoints`，明确说明并选择可覆盖的字体或替代符号；不能把写入 manifest 当作缺字已修复。
- 交付时说明覆盖检查结果，以及是否重新生成或更新了子集文件。

源字体保留原授权，发布固件前应确认该字体允许子集化及嵌入分发；本次不改变字体授权。

## 运行时

- 字体轮廓直接从 Flash 映射数据交给 FreeType，字号变化后重新栅格化，支持 4bpp 灰度字形。
- 系统 UI 使用独立 TextRenderer，不借用正文或下一页预绘制的缓存。最多保留 12 组字号，但不再逐实例预留 128 KiB：每个实例的字形池从 8 KiB 起步，按实际字形需求增长。当前系统字号的主字体上限 128 KiB；辅助字号按字号平方设定 16–64 KiB 上限；内置兜底及备用字体上限 32 KiB。字形元数据和字宽缓存也按角色缩小。全部 UI 字形池共用 768 KiB 预算，增长前淘汰其他最久未使用的字号组，当前绘制字号组不会被淘汰。此预算不包含 FreeType 数据、索引及流缓存；不是整个 UI 渲染器的总内存上限。
- 同一个 SD 字体文件的各字号共用一个文件句柄及 64 KiB 字体流缓存；各字体实例和字形池仍独立，动态文件名／歌词与静态文案在当前字号池中按原有淘汰规则复用空间。尚未建立固定文案常驻区与跨字号共用的动态位图区。共享缓存以路径、文件大小、修改时间匹配，最后一个引用关闭时释放；文件 seek/read、缓存窗口及引用生命周期统一加锁。
- 字体重置／字号组淘汰同时归还字形元数据及查找表容量，避免只清空数量却保留分配。正文保留原有固定容量策略。原生 `tools/test_ui_font_budget.py` 验证增长后像素数据保留、总预算、当前组保护、分配失败回退及正文固定池不变。
- UI 子集无法预知任意书名、文件名、短信、搜索结果。优先使用所选字体，缺字回退内置字体，再按需加载一份 SD 完整字体；优先 `pingxianzhensong.ttf`、`Hei.ttf`，然后文件名排序后的首个可用字体。没有覆盖该字的字体时显示缺字框，不能保证任意 Unicode 全覆盖。
- 所选 SD 字体缺失时使用内置字体显示 UI，原选择保留。重新插卡后重启或重新选择字体以重新加载。
- 原 `lv_font_SourceHanSansNormalCN_36.c` 不再参与 M5GFX 构建，包装符号与应用调用已移除；源文件留存但不会占用固件空间。

## 阅读器兼容

TTF/OTF 从 SD 卡按窗口读取，不要求整份字体驻留 PSRAM；文件不再受人为的 32 MiB 上限限制，只检查文件非空并能由平台文件偏移及 FreeType 流字段表示。日志中的 `file_bytes` 是字体文件字节数，不是显示字号。预览和正文共用这项流读取规则。

阅读中点击“设置 → 字体”时，在原阅读设置浮层内显示字体二级列表，不再推入全屏字体选择 Activity。支持 `/sdcard/fonts` 下的 TTF、OTF、BIN，文件名排序；列表行高随系统字号调整，上下滑动翻阅、方向键移动焦点。当前已保存字体以 `*` 标记。

点击列表项只更新下方字体预览，不保存；底部“使用此字体”或确认键保存并返回设置，“返回”或返回手势只返回上一级。预览固定显示简体中文“同一个世界，同一个梦想”和英文“One world, One dream”，使用当前阅读配置的字号，不随系统字号或简繁转换而改变；复用正文的字体解码规则（BIN 仍遵循其固有字形尺寸）。使用独立 TextRenderer，64 KiB 字形池、4 个字体流窗口，仅加载当前候选字体，退出列表即关闭文件及释放缓存，不污染正文/预绘制的字形缓存。列表区相应缩短，预览区域不参与字体列表点击命中。

关闭整个设置后由原阅读器重新加载字体并排版；没有改变正文、页码或阅读进度的保存时机。RSS 继续保存到独立配置。过宽或异常字体仅裁剪预览边界，不缩小字号、不覆盖列表或按钮。

阅读字体仍使用原有独立设置与完整 SD 字体，不与系统字号联动。旧 `builtin:source_han_sans_cn_36` 阅读配置在启动时迁移到可用的 SD 完整字体：优先上述两个文件，否则按文件名选择第一份 TTF / OTF。用户原先选择的有效 SD 字体保持不变。没有 SD 完整字体时只能使用内置 UI 子集，普通书籍会缺字，需安装完整字体。

## 实机验证

1. 三种系统语言下打开主页、设置、键盘、文件管理器与计算器。
2. 调整 24 / 28 / 48 px，检查页眉、设置行、输入框及较长文案；布局仍为固定尺寸，超长标题按原逻辑省略。
3. 切换 SD TTF / OTF，重启检查持久化；移除所选字体检查内置回退。
4. 用不在 UI 文案中的中文书名/短信检查 SD 字体回退。
5. 正文阅读、预绘制翻页、字号切换及 RSS 阅读保持正常。
6. 恢复默认设置后回到内置 28 px。
