# 竖排与批注阅读：跨格式实施设计

状态：实施中。已接入 KF8 CSS flow 与 EPUB 文档级 CSS 方向检测、行内 sup/ruby 语义分离、按列分页/绘制、批注竖排命中、按书方向覆盖以及 TXT 手动竖排。固件编译已通过；真实设备上的版面、标点、旁注大小和进度兼容仍待验收，不能仅凭编译结果视为完成。

当前实现采用单线程主绘制路径，不旋转最终 framebuffer，也不改动 EPD 波形或扫描。`Auto` 仅识别受控的文档级 `vertical-rl`；原本没有方向声明的书继续横排。方向设置独立存储在 NVS，不改变旧的 `ReaderStyle` blob。

已知待完善项：ruby 目前显示旁注圆点并可点开正文弹层，尚未缩字排在基字旁；连续西文在竖排中暂时逐字直立，尚未按 CSS `text-orientation` 分组旋转；RSS 仍使用独立排版入口。设备首轮验收通过后再开放复杂旁注与跨格式回归，不把这些降级行为误称为完美还原。

## 1. 样本与现状

验证样本：`tmp/脂硯齋重評石頭記 ㊣.azw3`（约 1.75 MB）。这是未加密的 KF8/AZW3：PalmDOC 压缩、UTF-8 正文、584 条 PDB 记录、552 条正文记录。FDST 含正文与 CSS 两个 flow。CSS 在 `html` 上指定 `writing-mode: vertical-rl`，即字符自上而下、列从右到左，并指定 `ruby/rt` 等样式；不是扫描版图片。

样本正文约有 3,997 个 `<sup>` 起始标签、49 组 `<ruby>/<rt>`、156 个 `<sub>`，以及 678 个 `class="quote"` 诗文段落。数量是标签统计，不等于独立批注条数。它们的语义各不相同：

- 段落中插入的 `<sup>` 往往是脂批，可能很长；不能作为普通上标字符挤进正文。
- 某些 `<p><sup>…</sup></p>` 是独立成段的评语或诗文，不能简单隐藏成一个脚注标记。
- `<ruby>正文<rt>短注</rt></ruby>` 是依附于正文的旁注；标题也使用 ruby。`rt` 不是正文的下一句话。
- `quote` 与 `quotetitle` 是诗文/题名段落，仍属于正文内容，不应被批注规则误删。

当前 `MobiBook` 能读取 KF8 主 flow 并重建 section；`ReflowBook` 已统一 EPUB、MOBI/AZW、FB2、Markdown、微信读书的章节读取。`epub_parse_xhtml_blocks()` 会跳过 `<head>`，不读取外部 CSS；未知的 `sup/ruby/rt` 标签不会建立批注结构，里面的文字会被顺序拼入正文。`DocumentLayout` 只有按宽度断行、按高度分页的横排路径，`TextRenderer` 只有横向整行绘制，触摸脚注也按横向行坐标计算。因此“能打开 KF8”不等于“支持这本书的版式”。

## 2. 范围与用户行为

### 本期目标

1. 排版方向支持 `Auto / 横排 / 竖排（右起）`。`Auto` 优先采用书籍声明，用户可按书覆盖；未声明时维持横排。方向可以按章节变化，混排章节不把整本书永久锁定为一种方向。
2. 保留正文、批注和它们的关联。行内评语在正文位置显示可见标记，点击打开现有阅读器的批注弹层；独立评语保留为可辨认的独立块；ruby 短注在竖排时优先显示为旁注，在空间或字体不满足时仍能点击查看，不与正文串接。
3. EPUB、KF8/AZW3 与 FB2 共用文档级批注模型和排版/触摸逻辑。TXT、Markdown 可手动选择竖排；它们无可推断的“行内批注”语义时不做猜测。微信读书沿用 ReflowBook，RSS 与 TXT 目前另有入口，须通过适配器复用布局能力，不改变服务器评论含义。
4. 简繁转换、字号/边距/背景、阅读进度、章节跳转、图片、预取和全刷规则在横竖排下仍成立。默认横排不发生可见回归。

### 非目标

本期不实现完整 CSS 布局引擎、任意浮动框/多栏网页、复杂表格竖排、漫画图片中的文字 OCR、扫描版 PDF/CBZ 的重排，也不承诺原版四色批注的精确印刷复刻。颜色样式在墨水屏上用字号、线型、留白和灰度区分。DRM/KFX 仍不在范围内。

## 3. 分层架构

```text
EPUB / KF8-AZW3 / FB2 / Markdown / 微信读书    TXT / RSS
                ↓ ReflowBook                    ↓ 独立入口适配
                └──────── 各格式正文、有限样式、源位置 ────────┘
       统一文档模型：Block + InlineRun + Annotation
              ↓ 简繁转换与源/显示位置映射
       HorizontalPaginator / VerticalPaginator
              ↓ PageItem：文字单元、图片、注释触达区域
       TextRenderer + 对应阅读 Activity：绘制、命中、弹层
              ↓ 现有 EPD 刷新队列
```

格式层只解释标记语义，不放置像素；排版层只消费统一模型，不理解 AZW3/FB2 私有标签。现有 `EpubContentBlock → document_layout::Block → PageItem` 可渐进扩展，避免另建一套 AZW3 专用阅读器。TXT 现在由 `TxtBook::read_page()` 流式分页，RSS 有自己的文章解析/绘制路径；两者只接入共用竖排度量与 PageItem 几何，不强迫先把整本 TXT 装进 ReflowBook。单一方向的页面按一个坐标系绘制，不将整页旋转后再用横排命中算法“假装竖排”。

### 统一数据契约

建议增加：

- `WritingMode { Inherit, HorizontalTb, VerticalRl }`：文档/章节/块的有限方向声明。解析结果同时保留来源与用户覆盖值。
- `InlineRun { source_range, display_range, role, style }`：正文、短注基字、强调等语义范围。范围使用 UTF-8 字节边界并保证落在完整码点上。
- `Annotation { kind, anchor_source_range, content/target, source_id, presentation }`：`LinkedFootnote`、`InlineSup`、`RubyText`、`StandaloneNote`、`WereadComment`。内容本身不计入正文的显示位置；原始源位置仍可追溯。
- `PageItem` 的文字几何：实际矩形及方向、基字/旁注所在的 hit region，不再仅靠“本行文字前缀宽度 + y 行高”推算。

普通 EPUB/FB2 链接脚注继续用现有目标解析；内嵌批注将内容直接随章节解析并只保存本章节所需数据，不制造假 URL 或临时文件。现有 `FootnoteRef` 可以在第一阶段作兼容适配，但最终弹层入口应接收统一 `Annotation`，避免把所有评语都叫 footnote。

## 4. 格式适配

| 来源 | 方向发现 | 批注发现 | 处理边界 |
| --- | --- | --- | --- |
| KF8/AZW3 | 读取 FDST 非正文 CSS flow，解析章节 `<link>`/`style`/内联 `writing-mode` | `sup`、`ruby/rt`、普通链接与 filepos | 当前仅读主 flow，必须补只读 CSS 访问；不重新解压整本来寻找方向 |
| EPUB | 从 manifest/章节相对路径读取关联 CSS，加上 `<style>` 和内联样式 | `epub:type=noteref/footnote`、`role=doc-noteref`、`aside`、`ruby/rt`、`sup` | 只支持受控样式子集，不展开网络资源或无限 `@import` |
| FB2 | 文件/section 的有限样式；未声明时可手动覆盖 | `<a type="note">` 及 notes body、`sup`，保留 poem/cite | 在 FB2→虚拟 XHTML 转换时保留语义，不把 notes body 当正文重复排版 |
| MOBI6/KF7 | 无可靠 CSS 声明时横排默认，允许手动竖排 | filepos 链接和有限 HTML 批注 | 不把 `.mobi` 扩展名直接当作 KF8 能力判据 |
| Markdown/TXT | 不自动猜测；用户按书选择 | Markdown 显式脚注语法可单独接入；TXT 不根据方括号猜注 | 手动竖排是显示方式，不改变源文本 |
| 微信读书/RSS HTML | 默认维持现有横排；RSS 需独立适配，明确声明后才启用竖排 | 既有微信评论保持单独类型；RSS 的普通 HTML 注释按支持范围接入 | 不改变评论下载、EPD 刷新或在线请求时序 |

样式检测仅接受 `horizontal-tb`、`vertical-rl` 和兼容的 vendor 前缀；支持明确的 `html/body` 规则、内联声明与章节样式。按“用户覆盖 > 章节明确声明 > 书级声明 > 横排默认”决策。若 CSS 缺失、循环引用、超出大小限制或解析失败，记录原因并安全回退横排，不吞掉正文。缓存检测结果用文件大小/mtime、章节 href 和解析版本失效。

## 5. 批注解析规则

1. 首先识别显式脚注链接及目标，沿用现有可点击弹层；带脚注语义的定义内容不占正常分页空间。
2. `<ruby>` 中基字进入正文；`<rt>` 单独保存为 `RubyText`，锚定精确基字范围。不得将 `rt` 直接接在基字后。缺失基字、嵌套/不完整 ruby 时保留可读文本并计数告警。
3. 段落内 `<sup>` 若前后有普通正文，则作为 `InlineSup`：在原位置保留一个稳定、可点击标记，评语内容进入弹层；长批注只需渲染标记，不在每次翻页重新解析整个评语。
4. 若段落主体几乎全是 `<sup>`，作为 `StandaloneNote` 独立块排版，可用较小字号/灰度与边线区分；不能因“是 sup”而隐藏整段。阈值由解析后的可见字符占比与结构决定，先在样本上建立黄金用例，不使用固定字数一刀切。
5. `sub`、普通 `span`、诗文 `quote` 不自动归为脚注。未知标签默认保留其文字；结构异常时“正文可读优先于样式完整”。
6. 批注文本与正文分别执行简繁转换。转换后的锚点通过现有 `script_conversion` 映射重定位；源位置与章节 ID 保持不变，避免切换简繁后点击错位或阅读进度漂移。

弹层先沿用现有横向排版（无论正文方向），便于长评语阅读。后续可以增加“页面旁注模式”，但它是增强项，不应成为基础批注可读性的前置条件。命中区域按实际 glyph/列矩形建立，并给短注标记最小可点击面积；若同一点重叠多个注，先选最小、最明确的锚点。

## 6. 真正的竖排布局与绘制

`VerticalPaginator` 与横排分页共享 Block、源位置和断句基础设施，但以内容高度决定每列容纳量，列宽由字格、行间距和旁注带组成。第一列在阅读区右侧，列内字符从上到下；下一列向左，列不足时生成下一页。分页以“列”为孤行/寡行约束单位；显式 pagebreak、标题跟随段落、诗文换行及图片仍有效。章节可以声明横排覆盖竖排（例如封面或表格），在块边界换页，禁止同一个 PageItem 混用两个坐标系。

绘制需提供单 glyph 定位，而不是调用 `drawUtf8Line()` 后把整个 framebuffer 旋转：CJK 字形直立；西文连续片段按竖排规则旋转或直立，数字组合可做有限 `text-combine-upright`；`、。！？（）《》「」—…` 等标点要有竖排字形/旋转与偏移表。优先使用字体中的竖排替代字形；无替代时使用经过验证的逐字符旋转/位移表。短 ruby 在相邻旁注带用较小字号排列，不能遮住下一列；空间不足时只留标记与弹层。独立评语块可跨列/跨页，但锚点不可丢失。

绘制、下划线、点击、选择章节及页面跳转统一使用 PageItem 的方向与矩形。已有阅读背景、页眉隐藏、灰阶和 EPD 模式继续在最终 framebuffer 上工作；竖排不改变波形。手势的下一页/上一页逻辑以阅读器当前操作习惯为默认，列方向只决定文字顺序，避免首版反转物理触摸区造成误操作。

## 7. 设置、进度、缓存与并发

- 在阅读设置中提供按书生效的方向 `Auto / 横排 / 竖排`；本书持久化为独立小记录，不扩充现有 `ReaderStyle` 原始 NVS blob（它按结构体大小读取，有迁移风险）。必要时再增加全局默认选项。
- 进度继续保存章节与**源正文位置**，不保存“第几页”作为唯一锚点。去掉显示用批注文字时必须记录源→显示位置映射；从旧进度打开时先映射到最近正文锚点，不能因布局签名变化直接跳回开头。
- 方向、注释呈现策略、布局算法版本、字号/边距、简繁模式进入 layout signature；方向切换时清除当前页、下一页预取及 glyph 命中缓存并重新分页。封面/书架百分比按源位置保持稳定。
- CSS 只读取需要的资源并做有界缓存；当前章节批注与页面几何按需驻留 PSRAM，不为全书建立完整 DOM。标记/正文索引应以 O(n) 单次扫描完成，避免 3,997 处 `<sup>` 导致反复全文搜索。
- 预取只使用不可变的章节快照；EPD 扫描期间不并行修改其正在读取的 PSRAM framebuffer 或目标图。先完成主线程正确性，再恢复现有下一页预取；命中缓存以章节、方向及布局签名共同校验。
- 增加有限诊断：方向来源、CSS 命中/回退、批注各类型数量、解析/分页/绘制耗时、PSRAM 峰值、点击命中与失配。正常阅读不逐个打印批注。

## 9. 风险与回退

最大风险是把 `<sup>` 或 ruby 当普通文本/脚注处理造成内容丢失，以及“整页旋转”导致标点和触摸位置错误。因此阶段 1 先保证语义与横排可读，阶段 2 再启用竖排；任何无法安全识别的章节回退横排并保留全部可见文字。新排版特性以方向设置和解析版本隔离；关闭竖排或删除按书覆盖后，现有横排管线不需要迁移书库，也不修改原 AZW3 文件。
