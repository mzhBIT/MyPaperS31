# MyPaperP4 / MyPaperS31 双 Board 支持设计

日期：2026-10-01
状态：阶段 1 的 Board 骨架和构建入口已实现并完成编译检查，P4 实机回归待验证；S31 屏幕及外设驱动尚未接入。

## 1. 目标与约束

- 同一仓库、同一套应用与阅读代码，支持 MyPaperP4 和 MyPaperS31。
- P4 保留 ESP-IDF 5.3.5；S31 使用 ESP-IDF 6.1，不因新型号强制升级 P4。
- 用户已确认两块板使用相同屏幕，均为 1216×684，逻辑竖屏 684×1216；复用当前已标定波形。
- 两板屏幕接口不同：P4 为 16 位，S31 为 8 位；扫描数据打包与硬件驱动分别实现。
- 默认行为继续为 MyPaperP4；现有开发、烧录流程在过渡期间保持有效。
- 不迁移 Metalio 的整套 LVGL UI、阅读器、云端业务或波形裁剪策略。
- 第一阶段建立 Board 与独立构建配置，不改 GPIO、波形、刷新时序、依赖版本和现有根目录 sdkconfig。

## 2. 现状与硬件差异

本设计依据当前仓库源码，以及参考目录
`E:/opensource/Metalio-E-INK4-Plus-main` 的 config.h 和板级初始化。
参考工程声明屏幕为 ED047TC2；当前 P4 配置名为 E0470A01-AF-S。
本项目按用户确认将二者视为同款屏幕，但总线与实际电气参数仍分别验证。

| 项目 | MyPaperP4 当前实现 | MyPaperS31 目标硬件 |
|---|---|---|
| 主控 / IDF | ESP32-P4 / 5.3.5 | ESP32-S31 / 6.1 |
| 当前配置频率 | 360 MHz | 参考配置 320 MHz，实施时核实 |
| Flash | 32 MB | 参考配置 16 MB |
| PSRAM | Hex / 200 MHz | Octal / 200 MHz，容量待实板确认 |
| EPD 数据 | 16 位 | 8 位 |
| EPD OE / MODE | PCA9535 控制 | 主控 GPIO 控制 |
| 面板电源 / IO扩展 | TPS65185 / PCA9535 | TPS65185 / TCA9555 |
| 触摸 | GT911 | FT6336U |
| Wi-Fi | C6 Hosted，SDIO连接 | 主控原生 Wi-Fi |
| 板载音频 | ES8311，主控配置采样率 | BH1098G，UART控制 / I2S，参考路径16 kHz |
| SD | SDMMC 4-bit | SDMMC 4-bit |
| 前光 | 单路，GPIO24 PWM + IO1_2使能 | 冷暖双路，GPIO6 / GPIO7 |
| RTC | 当前未接入独立RTC | PCF8563 |
| 电池 / 充电 | 型号与能力待硬件确认 | BQ27220 / CX25601N |
| 其他 | ML307A、USB UAC 已实现 | SC7A20H、震动、物理按键；ML307/UAC按后续接线验证 |

引脚以板级配置为准，不在业务代码中散落硬编码。
S31 参考硬件有版本差异，如 XSTL、MODE、USB模拟开关连接，接入前须确认实板版本。
VCOM 独立配置：不得把参考工程的1200 mV直接覆盖P4当前1050 mV配置。

## 3. 架构边界

```text
应用 / Activity / 输入法 / 阅读解析排版 / 本地化
                    │
          公共服务与硬件能力查询
                    │
       ┌────────────┴────────────┐
       │                        │
  MyPaperP4 板级实现       MyPaperS31 板级实现
  IDF 5.3.5              IDF 6.1
```

### 3.1 目录规划（实施时创建）

```text
main/boards/
  Board.h                    BoardId、能力和统一访问接口
  Board.cpp                  编译期选择，禁止应用自行判断芯片型号
  common/                    可共用的逻辑
  MyPaperP4/                 引脚、初始化、外设适配
  MyPaperS31/                引脚、初始化、外设适配
main/platform/              必要的 IDF 版本兼容封装
configs/
  mypaperp4/sdkconfig.defaults
  mypaperp4/partitions.csv
  mypapers31/sdkconfig.defaults
  mypapers31/partitions.csv
scripts/                    分型号构建入口
```

先移动初始化与配置，不一次性重写所有服务。
M5GFX/M5Unified 中新增 board_MyPaperS31 所需适配；现有 M5.Display 调用保持可用。
参考工程使用LVGL不意味着本项目S31也需要引入LVGL。

### 3.2 Board 接口与能力

- BoardId：MyPaperP4、MyPaperS31；编译期选定，不做跨芯片自动探测。
- 初始化顺序、I2C访问、电源轨、触摸、SD、前光、音频后端由Board负责。
- 能力包括：RTC、电池监测、冷暖前光、震动、USB MSC、USB Audio、ML307。
- 区分编译支持、初始化成功、运行时设备在线，不能用一个布尔值混合表达。
- 未接入硬件的能力返回明确的 NOT_SUPPORTED；界面隐藏或禁用入口。
- 板级初始化报错可定位外设，非关键外设失败不应反复重启整机。
- 保留现有应用与服务API，通过内部后端分发，减少大范围UI修改。

## 4. 双 IDF 构建与依赖隔离

### 4.1 构建配置

| Board | IDF_TARGET | IDF版本 | 构建目录 | sdkconfig |
|---|---|---|---|---|
| MyPaperP4 | esp32p4 | 5.3.5 | build-p4 | build-p4/sdkconfig |
| MyPaperS31 | esp32s31 | 6.1 | build-s31 | build-s31/sdkconfig |

构建脚本显式选择Board、目标、IDF环境、SDKCONFIG与SDKCONFIG_DEFAULTS。
在新构建目录中传入目标，不在共享目录执行会改写配置的 set-target。
拒绝Board与目标不匹配、IDF版本不匹配、旧CMake缓存混用。
输出工程名可以暂时保留MyPaperP4以减少脚本破坏；运行日志和型号显示必须正确。

P4现有根目录sdkconfig/defaults和build先保留，不清空、不覆盖。
迁移时复制已验证的有效配置到P4 profile，并检查新旧构建结果。
S31不复用P4的内置LDO、C6 Hosted、CPU频率和引脚配置。
S31使用独立16MB分区方案；应用大小由实际编译决定，不盲目复用参考项目字体分区。

### 4.2 依赖不是仅靠 build 目录隔离

当前 main/idf_component.yml、dependencies.lock 和 managed_components 位于源码树，
Component Manager 在切换目标/IDF后可能重新解析或改变共享依赖。
当前 EXTRA_COMPONENT_DIRS 还显式引用Hosted相关组件。
因此，仅分开build目录不足以保证依赖隔离。

实施时须：

1. 盘点已修改的managed_components，区分上游包与必须保留的补丁。
2. 将必要补丁迁入可追踪的本地组件或明确的版本化补丁机制，禁止解析依赖时丢失。
3. 对Hosted、远程Wi-Fi、UAC以及芯片专用组件做目标条件选择。
4. 为两个profile固定经过验证的依赖版本与锁定结果，核实6.1的Component Manager行为。
5. 未完成独立依赖目录验证前，同一工作目录只允许串行切换构建，不声称可并行。
6. 若需要同时构建，使用同仓库不同worktree，分别管理managed_components、lock和build。

已确认本机 S31 的 6.1 环境位于 `D:/Software/esp32/.espressif/v6.1/esp-idf`；不使用现有5.3.5工具链编译S31。
M5GFX/M5Unified及JPEG、音频、TinyUSB的S31/6.1兼容性列入实施验证项，不能仅改版本约束强行通过。

## 5. 屏幕与波形引擎

### 5.1 共用内容

- 现有已标定波形及Fastest / Fast / Text / HD / Quality的逻辑含义。
- 4bpp绘图、目标灰阶量化、旧态/目标态转换、相位去重的算法。
- 阅读器图片页Quality、下一页清残影和周期全刷规则。
- 中性码掩码策略与异常后物理状态unknown规则。

### 5.2 独立扫描后端

P4保留现有LCD_CAM/GDMA实现；S31接入独立后端，可参考Metalio的LCD/RMT实现。
定义明确的准备相位、提交、等待完成、停止/失败恢复接口。
8位总线采用自己的像素顺序、行长度、padding、缓存对齐、DMA描述符和控制信号映射。
当前P4 Panel_EPD_2D内部的打包假设也要检查，不能只替换提交函数。
同一灰阶逻辑不意味着P4的扫描字节缓冲可以直接提交到S31。

S31行周期以当前16us作为初始验证目标，CKV有效保持时间、时钟与porch需逐项对照。
必须用单帧测试/逻辑分析验证，不能仅凭总刷新时间接近认为时序正确。
波形内容不改；若电气差异造成灰度变化，先排查时序与VCOM，不直接重标定LUT。

预热帧数与缓存槽位按实测生成时间及相位首次使用时刻确定。
P4的Quality预热14帧、DU4预热3帧只作为现状，不作为S31保证。
S31先采用完整准备的安全路径，再评估流水线；内存不足时明确失败或调整预算。
生产者失败/欠载必须终止、关电源并置物理状态unknown，禁止继续更新已知态。

### 5.3 内存与并发

- DMA描述符、ISR及紧迫控制路径优先内部RAM/IRAM，具体能力按S31驱动约束确认。
- 页面/图片/字形/波形大缓存优先PSRAM；不能照搬P4的DMA可访问性和cache操作。
- NVS/Flash写入与外部栈约束分别核实；不把所有任务直接迁到PSRAM。
- 不复制两个扫描引擎的大缓存；只编译并初始化选中Board的实现。
- 图片预取不得写正在扫描的缓冲；明确所有权、generation、取消和释放时刻。
- 原生Wi-Fi、SD、图像解码与EPD并发需要压力测试，不能把P4核亲和配置视为通用保证。

## 6. 外设与服务适配

### 网络

保持wifi_setting对业务的接口。P4后端继续C6 Hosted，S31后端使用原生Wi-Fi。
保留常开/省功耗、连接状态和应用网络需求语义。
S31未接ML307时不启动探测任务、不显示可用4G选项。
ML307后续接入与USB Host能力绑定，不能因为仓库有组件就默认支持。

### 音频

P4保留ES8311与已验证UAC路径。S31实现BH1098G控制/输出后端。
参考硬件由外部芯片提供I2S时钟，16kHz路径的通道、位宽和模式需实测确认。
音乐与收音机保留原解码链，按后端能力重采样；不得把16kHz限制施加给P4/USB DAC。
模式切换、音量、停止和退出须独立验证；首次接入不承诺BH蓝牙所有模式均可用。

### 时间、前光与电源

PCF8563接入现有时间服务，校时后更新系统时钟与RTC；统一UTC/本地时间约定，避免重复加8小时。
阅读时长与通话耗时继续使用单调计时，不改用RTC日期时间差。
两板共用亮度等级语义，但PWM极性、频率、上限分别配置。
S31冷暖色温为能力扩展，P4单路不显示色温设置。
电量/充电/按键/震动先完成基础驱动；自动休眠、电源轨切断后续独立阶段实施。
所有IO扩展操作采用串行访问与位掩码更新，避免前光/功放/EPD互相覆盖寄存器。

### USB与SD

继续保持SD本机挂载与MSC交给PC互斥；不得一边导出一边读书或写缓存。
S31核实HS口和ANA_SW的实际连接，独立实现切换、退出与重挂载。
MSC、Audio Host、Modem Host是否可用由能力与运行状态共同决定。
P4现有USB传输启动流程暂不改为另一种模式。

## 7. 分阶段实施与验收

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| 0 基线 | 固定P4提交/配置，盘点本地组件补丁，确认S31板版本与6.1路径 | 可重复构建P4，硬件信息与依赖清单明确 |
| 1 构建/Board骨架 | 分profile、能力接口、条件依赖，迁移P4初始化但不改行为 | P4构建与实机回归通过；S31基础工程可构建 |
| 2 屏幕 | S31 8位扫描、电源与M5GFX适配，共用波形 | 单相时序、黑白/灰阶/转移矩阵、连续刷均通过 |
| 3 基本交互 | FT触摸、SD、字体、前光、主页与阅读器 | TXT/EPUB/漫画可读，无坐标/灰阶异常 |
| 4 网络 | 原生Wi-Fi与常开/省功耗策略 | 配网、RSS、DeepSeek、微信读书/地图等网络流程验证 |
| 5 外围 | RTC、电池、充电、按键、震动 | 校时、时间显示、电量及外设失败降级正确 |
| 6 音频/USB | BH音频、音乐/收音机、MSC；Host按需追加 | 切歌/停止/退出不阻塞；SD所有权切换正确 |
| 7 性能/功耗 | 波形流水线、预取并发、待机 | 无欠载/看门狗/残影累积，睡眠与唤醒可恢复 |

每阶段单独提交、同时回归P4；驱动和波形标定不混在同一批修改中。
涉及硬件验证时由用户烧录测试，本设计不包含自动刷机授权。

## 8. 最小测试矩阵

- 构建：P4/5.3.5、S31/6.1独立配置与依赖；切回P4无配置污染。
- EPD：全部模式、黑白起点、16灰转移矩阵、主页反复翻页、图片页与后续清理。
- 阅读：TXT/EPUB及其余支持格式，简繁转换、竖排、脚注、阅读时长和退出保存。
- 并发：下载图片+翻页、预解码+刷新、网络音频+UI刷新；统计内部RAM/最大块/PSRAM/欠载。
- 生命周期：返回、取消、无SD、无网络、外设初始化失败、USB拔插及资源重新初始化。
- 电源：前光切换不改变EPD控制位；RTC校时不改变耗时计时；待机恢复不遗留失效句柄。

## 9. 风险与待确认项

1. ESP-IDF 6.1安装路径、S31硬件版本和PSRAM容量。
2. M5GFX/M5Unified的S31适配范围与IDF6.1内部API差异。
3. S31扫描/DMA/cache能力和可持续相位生成速度。
4. BH1098G音频模式、实际采样格式、模拟麦克风与扬声器连接。
5. USB接口/ANA_SW/VBUS接线及是否计划接入ML307或USB耳机。
6. 双IDF依赖锁与现有组件补丁保全；未解决前不并行操作共享managed_components。

引用参考代码时保留其许可与版权声明，逐文件核查许可，不把仓库总许可视为所有第三方文件的许可。
