# 驱动帧逐帧耗时诊断

`Panel_EPD_2D.cpp` 在驱动帧生成时只记录时间，在扫描结束、生产任务退出、面板断电和物理状态提交后打印 `drive frame (after refresh)`。

- `type`：波形类型；`unique0`：去重驱动帧编号；`phase0`：首次使用该帧的扫描相编号。两个编号均从 0 开始。
- `stage=prime`：扫描前生成；`stage=worker`：后续生产路径生成（也可能在动画准备阶段按需生成，不表示一定与扫描重叠）。
- `lut`：驱动查找表构建时间。
- `clear`：输出帧清零时间；全屏覆盖写入、不需要清零时为 0。
- `pixels`：输入读取、转换索引编码、查表、打包排列及输出写入的合计时间。没有在逐像素热循环中分别插入时间戳。
- `total`：该帧的生成耗时，包括上述阶段及少量函数、记录开销。不包括等待环形缓存槽释放的时间。
- 所有时间单位为微秒，属于经过时间，可能包含任务抢占。

DU4 和 GC16 双像素查表路径支持阶段细分。通用生成路径只记录 `total`，其 `lut/clear/pixels=0` 表示没有单独测量，不代表这些工作没有耗时。

三帧融合路径显示一条 `count=3` 的共同测量，从 `unique0` 开始连续三张帧共用该时间。不能把共享输入循环准确拆成三张独立耗时，因此不将总值均分后冒充实测；其余帧 `count=1`。

记录表有 64 项，采用静态存储避免增加显示任务栈压力；仅在任务/阶段边界取时间戳。逐帧日志仍会增加刷新后的串口输出时间，性能验证完成后应移除或关闭这批诊断。

## GC16/HD 转换索引实验

`MYPAPER_EPD_2D_GC16_PAIR_INDICES=1`（默认）在至少三张驱动帧时启用，支持全屏及局部 GC16/HD。分配扫描帧后，按本批次旧画面和目标快照构建一次 16 bit 双像素索引，再供所有预热和后台驱动帧复用。索引保存在可复用的面板 PSRAM 工作区，1216×684 需要 831744 字节；每批只重建更新区域，区域外旧索引不读取。局刷仍先清零输出帧，首尾不完整16像素组只查询区域内的索引，区域外保持中性码。不跨批复用有效内容，不修改波形、预热数量或物理状态提交。分配失败时走原实现。

刷新后新增 `pair indices (after refresh): enabled=1 build=... us bytes=831744`。对比时除逐帧 `pixels` 外，必须把一次 `build` 时间计入启动成本；分配及构建发生在工作区准备阶段，不包含在逐帧 `total` 内。将配置宏设为 0 可以恢复原路径做 A/B 测试。

`tools/test_epd_pair_indices.cpp` 穷举 65536 种键，检查 48 张随机合法驱动表的输出组，并验证目标变化后重建索引。输出排列仍复用原 `permute_epd_output()`。
