# 路线规划内存缓存

- 驾车、步行、骑行分别保留最后一次成功规划的结果。
- 点击方式标签只恢复缓存，不发起网络查询；未规划的方式需点击“规划”。
- 点击“规划”重新查询当前方式，成功后替换该方式缓存。失败不覆盖之前成功的缓存。
- 更换起点、终点或交换起终点，清空三种方式的缓存，避免显示不匹配的路线。
- 缓存由地图 Activity 持有；显示路线并返回地图后，重新进入规划页仍保留起终点、方式及结果。退出地图释放，不写 SD/NVS，不跨重启。

## 内存与线程

`MapRouteCache` 将几何坐标、UTF-8 指引文本序列化至连续 PSRAM 缓冲，避免默认 STL 分配器将三份缓存放入内部 RAM。少量摘要及索引保留在对象中；当前显示结果恢复到既有 `AmapRoute`，仍沿用现有绘制逻辑。

每种方式最多 512 点、128 条指引、每条最多 2048 字节，与接口解析上限一致。最大有效数据约 265 KiB/方式，三份约 794 KiB；原子替换一份时短暂同时保留新旧缓冲。分配失败不影响当次结果显示，也不破坏已有缓存。

缓存仅由 UI 线程操作；网络任务通过既有完成标志交回结果后再缓存。不修改 EPD、DMA、刷新任务或图像处理逻辑。

可观测日志：`MAP_ROUTE: PSRAM cache stored/hit mode=... bytes=...`。
