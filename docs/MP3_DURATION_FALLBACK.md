# MP3总时长备用解析

仅在Espressif提取器读取MP3失败或返回时长0时启用，其他格式保持原有路径。
只补充总时长，不改变解码、采样率转换、输出设备或EPD刷新。

- 跳过ID3v2.2/2.3/2.4标签及v2.4尾标，不扫描封面图片内容。
- 排除尾部ID3v1、APE标签；同步头必须符合Layer III格式，并验证下一帧。
- 优先读取Xing/Info或VBRI帧数，按帧采样数、采样率计算时长。
- 无可用时长头时逐帧累计，支持MPEG1/2/2.5及变码率，不按单帧码率估算整首歌。
- 使用32KiB PSRAM顺序窗口，在窗口中按帧长度定位帧头。窗口起点按512字节对齐，文件位置连续时不额外seek。保持逐帧校验，不依赖CBR抽样估计。
- 不支持free-format（码率索引0）；损坏的帧链、无效标签、超出预算都返回未知，不显示不可靠的部分时长。
- 播放前仅执行时长头检查（mp3_duration_read_tags），不进行整首扫描。无时长头时先播放，待播放器就绪并预留200ms后在core0/priority1后台扫描。后台每个32KiB窗口延迟1个tick，30秒总预算，扫描缓存完成后释放。
- 后台只有一个worker、一个最新待处理请求。停止、切歌、deinit递增generation；扫描逐窗口检查取消，写回时在计时锁内再次匹配generation，防止上一首结果污染下一首。音乐页既有计时轮询自动读取新时长。
- Worker首次需要时创建，4KiB栈位于PSRAM，空闲时阻塞于队列。任务和一个请求槽保留复用；扫描缓冲及独立FILE句柄在每次结束/取消后释放。没有任务强制删除、同步join、NVS/SD时长缓存，也没有修改音频输出或EPD刷新。
- 恢复文件原读取位置。日志记录source、耗时、stage、reason、首帧偏移、已扫描帧数、读取次数和实际请求读取字节数；预算取消后也保留诊断信息，仅清空时长结果。

Xing布局核对参考：[LAME官方VbrTag实现](https://github.com/lameproject/lame/blob/master/libmp3lame/VbrTag.c)。实现为独立的小型只读解析器，不引入LAME依赖。

主机测试：tools/tests/mp3_duration_test.c，覆盖时长头、CBR/VBR逐帧扫描、ID3尾标、MPEG2、文件位置恢复、截断末帧、损坏帧链和预算取消。
原始《毛阿敏 - 相思.mp3》已在PC验证：7354403字节、首帧偏移2373、7036帧、44100Hz、时长183797ms，无可用Xing/VBRI时长头。

64字节小窗口方案实机在3001ms预算截止时只扫到4562帧，已执行4534次读取；减少应用层读取字节并未解决SD频繁定位和小读取的开销。256KiB窗口方案实机在3008ms截止时扫到4801帧、读取约5MB，仍无法完成。因此不继续增加同步阻塞时间，改成后台补齐，并将窗口缩回32KiB以减小单次占卡时间。PC完整逐帧结果仍为183797ms；实机完成时间及同时播放的流畅度需要验证。

预期日志：播放前`MP3 duration fallback`显示`reason=no-duration-tag frames=0`，这是正常延后；之后`MP3 duration background`显示`ok=1 applied=1 duration=183797`。取消/过期结果不写回；后台超出30秒仍显示未知。

Windows原文件诊断工具：tools/tests/mp3_duration_probe.c，传入音频路径，使用同一解析器输出上述统计。
