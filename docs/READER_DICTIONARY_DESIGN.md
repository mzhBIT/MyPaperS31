# 阅读器离线词典查询设计

日期：2026-10-01
状态：设计阶段，尚未实现；本文不代表现有固件已支持查词。

## 1. 目标与边界

在阅读过程中提供可开启/关闭的离线词语查询，初版支持英文→中文、中文→英文。通过长按选择正文词语，在阅读页面内显示释义浮层，不新建全屏 Activity、不连接网络、不修改书籍原文件。

“内置词典”指查询功能集成到固件；大体积词库安装到 SD，不编译进 Flash。MyPaperP4 与 MyPaperS31 共用转换格式、查询服务、选词接口与浮层，硬件差异仅由 Board/显示适配处理。S31 完整阅读应用尚未接入，本功能不能视为同时完成了 S31 应用移植。

初版不包含整句机器翻译、OCR、发音播放、生词本和联网补全。不保证中文歧义词的解释与上下文完全一致，也不将英汉释义倒排后当作汉英词典。

## 2. 当前可复用能力与缺口

- `main/activities/EpubReaderActivity.cpp`：已有脚注定位、弹窗、分页和微信读书评论逻辑；可借鉴交互，但脚注引用定位不等同于任意正文字符定位。
- `main/activities/ReaderActivity.cpp`：TXT 使用独立阅读路径，必须另行接入，不能只修改重排阅读器。
- `main/parser/reflow_book.*` 与通用排版模块：提供重排正文来源，查词应基于正文/排版对象，不从像素截图取字。
- `main/ui/script_conversion.*`：已有简繁转换；查词需要兼容显示文字与原文位置映射。
- `main/storage/app_paths.*`：新增词库路径统一在这里管理，不在各应用中分散写路径。
- 系统已有多语言、NVS 设置、浮层输入和 EPD 刷新策略，应复用这些基础能力。

当前正文长按会打开阅读设置的 Chapters 标签。新功能必须明确分流，避免直接抢占全部长按事件。通用选词命中、词库加载器、查词浮层和 PC 转换工具均为待新增内容。

## 3. 用户交互

### 3.1 开关

阅读设置 Beauty 标签增加“词典查询”开关，默认关闭。英文/简体/繁体系统语言均本地化。保存为全局阅读偏好，使用 NVS 独立键，不随书籍单独覆盖。

关闭时：不创建查询任务、不读取词库、不生成额外的逐字符命中缓存，保持原有触摸行为。开启时：首次查询惰性加载词库索引；尚未安装词库允许提示，但不能影响正文显示。

Beauty 已有多个设置项，新增入口不得挤压到屏幕外；根据现有面板布局增加滚动/分页或紧凑行布局，不缩小到难以点击。词库安装说明、名称/版本和可用状态可放到词典二级配置中，初版不增加复杂的多词库管理。

### 3.2 长按分流

事件优先级：已打开的浮层/设置 → 返回等导航事件 → 正文查词 → 原有阅读手势。

- 查词开启且长按命中正文文字：启动选词与查询，不打开 Chapters。
- 查词开启但长按命中空白、图片或不可选择区域：保留原有长按行为。
- 查词关闭：长按完全保持原逻辑。
- 普通点击脚注和评论仍按原逻辑处理；查词不要求关闭阅读美化下划线或公共评论。
- 初版只选正文，不选择页眉、页码、脚注标记、ruby 小字等装饰元素。脚注弹窗内部查词可后续扩展。
- 查询浮层存在时不穿透到正文翻页；关闭后不改变阅读进度。

### 3.3 选词与浮层

英文自动选择完整单词；中文按词库匹配长按字符附近的词语，提供更短候选和单字兜底。浮层显示选中词语、音标或拼音（词库有则显示）、词性和释义。

浮层放在屏幕下部，尽量避开选中文字；提供关闭、调整范围及释义翻页。初版范围调整可用“向前/向后扩展、缩短”按钮，不要求实现高频拖动选词手柄。另提供“编辑查询词”入口，调用现有浮层键盘，作为中文歧义和识别错误的兜底。

高亮使用框线或细线，不大范围反色；复用系统文本渲染、排版和当前字体，词典浮层只显示释义，不重复展示长段引用正文。长释义按需分页、限制条目数及总字节数，不无限扩大内存。

## 4. 词库来源与安装

初版推荐两份独立数据源：

| 方向 | 数据源 | 导入内容 |
|---|---|---|
| 英→中 | [ECDICT](https://github.com/skywind3000/ECDICT) | 英文词条、中文释义、音标、词性及可用的词形信息 |
| 中→英 | [CC-CEDICT 官方下载](https://www.mdbg.net/chinese/dictionary?page=cc-cedict) | 简体/繁体词头、拼音、英文释义 |

转换前核查所选版本的数据授权，输出包保留原来源、许可证、版本/日期和转换工具版本；词库授权与固件代码授权分开处理。不随意打包来源不明的商业词典。

初版转换器直接读取 ECDICT CSV 与 CC-CEDICT UTF-8 文本。未来可导入 [StarDict 格式](https://github.com/huzheng001/stardict-3/blob/master/dict/doc/StarDictFileFormat)，但不把其 `.dict.dz` 随机解压等兼容工作作为首版前置条件。

拟定安装目录：

```text
/sdcard/.reader/dictionaries/
    en_zh.bin
    zh_en.bin
    manifest.json
    LICENSES/
```

这些是新增路径，不替代现有拼音输入法或 OpenCC 的词库。词库由 PC 生成，通过现有 Wi-Fi 文件管理或 USB MSC 上传。USB MSC 模式下设备不能同时查询 SD。

实施到转换器阶段时再告知用户准备/下载哪些原始文件及执行命令；文档阶段不要求用户先处理。

## 5. PC 转换与二进制格式

拟新增 `tools/build_reader_dictionary.py`、格式说明与测试。词库格式版本 v1 使用固定小端整数、UTF-8 字符串，不直接写入 C/C++ 结构体，不受编译器填充或指针宽度影响。

逻辑组成：文件头 → 分块目录 → 排序词条索引 → 词头字符串区 → 释义区 → 可选别名/词形表。

文件头至少包含 magic、版本、方向、条目数、各区偏移/长度、最大词头长度、文件总长和校验信息。词条包含词头偏移/长度及释义偏移/长度；禁止在设备端依赖 CSV 或逐行扫描源文件。

转换规则：

1. 过滤空词头和无效 UTF-8；统一换行，保留同词多义，不简单用最后一条覆盖。
2. 英文索引使用固定的大小写归一规则，显示词头保留原文；中文简繁词头建立别名索引，共享释义记录。
3. 排序规则由转换器和固件共同定义：规范化 UTF-8 字节序，不依赖系统 locale 排序。
4. 按词头和索引大小分块，目录保存每块首词与范围。目标块大小 8–16 KiB，可按实测调整。
5. 同词重复内容去重，控制单条释义长度；截断必须落在 UTF-8 边界，记录截断标志。
6. 源数据存在明确词形信息时生成词形→词条映射；不能凭后缀处理制造不存在的释义。
7. 输出写入临时文件，生成成功并验证后替换最终文件，避免使用半成品。

格式最终字段、长度上限与版本迁移规则在阶段 1 冻结，并以转换器/固件共用测试向量验证。转换器先对全文件做完整校验；设备每次查询不重新校验整份大词库。

## 6. 设备端查询服务

拟新增 `main/dictionary/` 模块：格式加载、索引查询、规范化、词形处理、查询服务与结果对象。与 Activity 和 Board 解耦，数据格式可用 PC 测试程序验证。

### 6.1 索引和资源预算

- 打开词库时校验头、版本、方向、区间越界、排序目录与条目长度。
- 小型分块目录常驻 PSRAM；索引块按需读取，释义按偏移读取。
- 近期查询结果与索引块使用有上限的 LRU，不全量加载词库，不建立海量 `unordered_map`。
- 初始预算目标：目录不超过 512 KiB、索引块缓存不超过 64 KiB、结果缓存不超过 64 KiB；超过预算时应拒绝加载或退回更稀疏索引，不能隐式增大内部 RAM 占用。
- 临时缓冲优先放 PSRAM；内部 RAM 仅保留驱动必需资源、控制结构与必要任务资源。任务栈位置按 Board/IDF 的安全能力确定，不能盲目迁移。
- 文件缺失、损坏、SD 卸载或内存不足均返回明确错误，正文仍可阅读。

初始性能目标：热查询低于 50 ms，冷查询低于 200 ms。它们是待实测目标，不是已验证承诺；日志区分规范化、索引读取、查找和释义读取耗时。

### 6.2 英文查询

顺序：原词匹配 → 大小写归一匹配 → 词库词形映射 → 有限的规则候选 → 提示未找到。

保留合法的词内撇号/连字符。合并因分页排版生成的英文断词，不无条件删除原文本中的所有连字符；遇到多个合法原形显示候选，不强行选定。初版允许编辑查询词，不声称复杂词形均能准确还原。

### 6.3 中文查询

从命中字符附近获取同段落的有限上下文，枚举所有覆盖该字符的候选子串，而不是只从命中字符向右匹配。按词库精确命中、长度和位置等规则排序；最长词优先仅是启发式，应允许用户切换短词。

中文候选初始上限：命中点前后各 8 个汉字，候选长度最大 16 个汉字，并受词库声明的最大长度约束。不跨图片、段落或脚注边界；可以跨视觉换行/竖排换列，边界词上下文按需补取。

简繁词头直接通过 CC-CEDICT 别名匹配；只有缺失时才考虑现有 OpenCC 查询归一，并保留原始查询词。查词绝不因此切换书籍的简繁设置。

### 6.4 异步、取消与 EPD

UI 只提交请求和接收结果，不在触摸回调中等待 SD 查询。只允许一个受控查询工作任务；新请求覆盖尚未执行的旧请求，取消已过期的结果，不为每次长按创建新任务。

请求携带 generation、书籍/章节/页身份、选区及词库版本；翻页、退出、改字号、改排版或替换词库后结果必须失效。工作任务不持有 Activity 指针，不调用 M5GFX，不更新正在使用的绘图缓存。

遵守已有 EPD/SD 资源协调机制：波形扫描期间延期词库读取和结果绘制，不修改刷新任务优先级、核心、波形或缓存写回策略。主线程收到结果后在可刷新时更新浮层。首次开词库的大量读取不能与 EPD 帧生产争用。

阅读过程中不保存查词记录。关闭功能时取消请求，待工作任务安全退出后释放句柄和缓存，不强删正在读取 SD 的任务。

## 7. 通用文字定位与格式兼容

拟新增一个与坐标和文字来源有关的公共接口，概念返回值包含：

- 页面上的可选择文字片段及布局范围；
- 显示文本中的 UTF-8 字节范围（必须落在字符边界）；
- 规范化查询词；
- 原文锚点及显示→原文映射；
- 高亮区域列表、横排/竖排信息和页面 generation。

字节偏移、Unicode 字符序号和屏幕像素不可混用。简繁词组转换可能改变字符数量，必须复用/扩展现有范围映射，不假定一字对应一字。

定位只针对当前页：先按行/列命中，再依据真实排版 advance、字间距、两端对齐间距和竖排旋转位置找字符。不能通过“x/字号”估算，也不为整章持久化逐字符矩形。只在需要时生成当前行/列的位置缓存。

| 内容路径 | 首版接入方式 |
|---|---|
| TXT | 使用解码后文本与当前页行布局，保留文件字节锚点；GBK/UTF-8 等统一在解码后查询 |
| EPUB、MOBI、AZW/AZW3、FB2、DOCX、Markdown | 在重排页面对象上命中正文，复用同一查词服务；不为每种容器重复写查询引擎 |
| 微信读书正文 | 走重排正文定位，点击评论/脚注与长按查词分别分流；不查询网络评论接口 |
| RSS 正文 | 依据实际使用的文章布局接入适配器，不能仅因“有图文”就假定与重排阅读器相同 |
| ZIP/CBZ 漫画、扫描图片 | 无文本层，首版不支持 |

竖排文字按真实列顺序还原词语，基字可查询，ruby 不加入正文查询词；行内批注若作为实际正文片段排版，可查询该片段但不跨正文与批注拼词。链接脚注标记本身保持原点击行为。

## 8. 设置、浮层和刷新约束

复用阅读设置、系统字体、多语言与弹窗基础设施，新增词典专用浮层控制器，避免把词典状态混进脚注/评论数据结构。设计独立 `DictionaryEnabled` 设置及词典 UI 文案，不使用未本地化的硬编码提示。

浮层的释义分页复用现有文本排版能力，可使用可读的横排；不强制继承正文竖排，否则英文长释义难以阅读。

显示/关闭浮层与高亮时沿用原刷新策略，不永久改变用户阅读模式，也不破坏图片页 Quality、后续清理页和周期全刷计数。若关闭浮层恢复图片区域，应由原阅读刷新策略决定使用 Quality，不能直接强制 Text。

释义 UI 初始限制：每次最多显示 8 个候选词条、总文本不超过 16 KiB，超出时明确提示更多内容未显示。设置开关只在用户修改时保存，不在每页/每次查询中写 NVS 或 SD。

## 9. 实施顺序与验收

### 阶段 1：格式与查询基础

冻结 bin v1；编写 PC 转换器、示例小词库及测试；实现加载、分块索引、释义读取和边界校验。再指导用户转换安装正式词库。

验收：随机抽查与源数据一致；同词多义、简繁别名、大小写、损坏文件和最大长度均有测试；无全词库扫描。

### 阶段 2：英文选词与查询浮层

接入重排阅读器与 TXT，增加开关、英文定位、高亮、异步请求和释义浮层。保留长按 Chapters 的分流，提供编辑查询词入口。

验收：不会跳出正文；英文跨行/断词可查询；取消、翻页和退出不显示过期结果；关闭后恢复原手势。

### 阶段 3：中文词语与简繁

加入覆盖命中点的中文候选生成、范围调整、单字兜底和简繁别名；校验词组转换后原文映射。

验收：长按词中间也能找到整个词；歧义可切换候选；简体/繁体、标点和跨行中文结果正确。

### 阶段 4：竖排、在线正文与格式回归

校验竖排、ruby、批注、脚注和微信评论；单独接入 RSS 适配器；逐项测试 TXT/EPUB/MOBI/AZW3/FB2/DOCX/Markdown 等格式。

验收：不串选小字/页眉；普通点击脚注/评论不变；图片不误触查询；不会影响阅读进度、时长和显示模式。

### 阶段 5：性能与双 Board

测冷/热查询、任务栈水位、内部 RAM 最大块、PSRAM 峰值和 SD 读取次数。持续翻页、查词、取消、图片下载并发时检查 EPD 欠载与显示残影。S31 在完整阅读应用接入后再做同样回归，未接入前仅能验证词库格式/查询模块的编译兼容性。

## 10. 测试与后续扩展

PC 测试覆盖：中文重复词头、英文不规则词形、UTF-8 边界、大小写碰撞、长释义、越界偏移、文件截断、排序不一致及版本不匹配。

实机测试覆盖：开启/关闭、无 SD/无词库、退出/返回、快速连续查询、字号/字间距/行距变更、隐藏页眉、横竖排、简繁转换、背景图片和 Quality 清理规则。

性能日志只记录查询词、阶段耗时和资源摘要，禁止高频逐字符日志；正常阅读不额外产生查词日志。

后续可以新增 StarDict 导入、生词本、整句联网翻译与 OCR，但应通过独立扩展实现，不改变首版离线词语查询的默认行为。
