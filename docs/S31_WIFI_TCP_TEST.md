# S31 临时 TCP 接收测速

> 历史调试记录：2026-10-31 已移除此临时接收任务、5001 端口监听及配套 PC 脚本。当前传输应用仅运行正常 HTTP 文件传输服务。

用于区分 Wi-Fi/TCP 接收链路与浏览器、HTTP、SD 写入的耗时。仅 S31 编译启用，
进入 Wi-Fi 传输或热点传输页面时自动监听 TCP 5001，离开页面时停止任务、关闭连接、
释放缓冲，再停止 Wi-Fi。测试启动失败不影响原文件传输。此端口不支持 iperf 协议。

1. 烧录本次固件，进入传输页面。确认日志 `TCP_RX_TEST: listening port=5001`。
2. PC 连接同一网络；热点模式连接设备热点，不要同时执行浏览器上传或下载。
3. 在工程目录执行（路由器模式把 IP 换成页面显示的地址）：

   ```powershell
   python tools/wifi_tcp_test.py 192.168.4.1 --seconds 30
   ```

4. 保留设备端 `TCP_RX_TEST` 的 `connected`、`progress` 和 `complete` 日志。
   以设备实际接收字节、时间和速率为准。PC 的中途 sent 计数包含尚在发送缓冲中的数据；
   结束时脚本半关闭发送并等待设备关闭连接，以排空发送队列。无数据超过 5 秒时报错，
   结束排空最长等待 15 秒。若测试中离开传输页，结果属于中断测试。
5. 分别测试热点模式和路由器模式；需要抓包时过滤 `tcp.port == 5001`。

接收端只做 select/recv 和字节统计，不解析 HTTP、不写 SD、不发送应用层响应。
使用 32 KiB PSRAM 接收缓冲、4096 字节任务栈、优先级 5、不绑核；与 HTTP 默认优先级一致。
空闲 select 最长 200 ms；持续收包每 250 ms 至多让出一个系统 tick，保证空闲任务运行，
没有逐包固定延时。每 2 秒记录吞吐，客户端正常关闭或出错时记录总量。

若仍只有几十 KiB/s，排查重点在公共 Wi-Fi/TCP 通路；若明显提高，再比较 HTTP 任务的
栈位置、收包和文件处理。测试不能直接区分 Wi-Fi 驱动、协议栈调度和无线重试，
也不等同于官方 iperf 基准。诊断结束后可删除 `TcpReceiveTest.h` 及传输活动中的三处接入。
