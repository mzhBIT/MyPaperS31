# 独立模拟器固件与重启切换

## 目标与实施顺序

当前系统保留阅读、网络及所有应用；模拟器编译为另一份应用镜像，共用引导程序及分区表，重启后独占 MCU、SRAM、PSRAM、显示及输入。现有 U 盘仍是主固件的启动模式，不另占应用分区。

1. S31 双固件骨架：主系统入口、镜像身份验证、独立显示/触摸返回页、单次启动与烧录检查。用户已验证双向切换成功。
2. GB 核心、SD ROM 浏览、存读档与独立连续扫描一起接入。按用户要求，不以现有 2D 引擎作为过渡后端。
3. 实机验证 Paperboy 式行扫描、四级空间灰度、四次驱动计数、输入、暂停与返回，再优化帧率及驱动时长。
4. BH1098G 独立外放已接入并通过本机编译/原生测试，待实机确认；电量显示/功耗与长期运行后续推进。

**模拟器仅支持 S31，不开发 P4 兼容。** 顶层及独立组件 CMake 都限制 `esp32s31`；后续不能添加自动回落到阅读 2D 引擎的逻辑。原 ESP32-S3 镜像不能直接使用；S31 使用 IDF 6.1。项目内保持 `MYPAPER_FIRMWARE=System` 默认，模拟器使用 `Emulator` 和独立构建目录。

## S31 分区契约（16 MiB）

| 标签 | 类型 | 地址 | 大小 |
|---|---|---|---|
| nvs | data/nvs | 0x9000 | 0x6000 |
| phy_init | data/phy | 0xF000 | 0x1000 |
| factory | app/factory | 0x10000 | 8 MiB |
| emulator | app/ota_0 | 0x810000 | 4 MiB |
| otadata | data/ota | 0xC10000 | 8 KiB |

结束地址 0xC12000，剩余 0x3EE000。主系统与 NVS 地址均不移动；ROM 和存档放 SD，不嵌入 Flash。两份镜像的分区表必须一致。此处使用 OTA 启动选择机制切换两个用途不同的应用，并非为主系统提供 A/B 在线升级槽。

## 启动与返回

主系统先查找 `emulator`，核对 ESP 应用描述中的项目名为 `MyPaperEmulatorS31`，然后使用 `esp_ota_set_boot_partition()` 完整校验镜像并选择下一次启动目标。分区缺失、镜像未安装/损坏、项目名错误时留在主系统，不重启。

入口只从系统主页进入。切换需等待 EPD 空闲、网络配置/校时和微信读书存储事务结束，停止音频/USB 后再改启动选择。切换过程在主任务执行，不在触摸回调或后台 PSRAM 栈上写 Flash。

模拟器在 `app_main` 最早阶段校验并把下一次启动目标恢复为 `factory`；成功后才初始化显示。它不会立即重启，因此仍运行模拟器；用户返回、复位或之后的异常重启回主系统。此机制不覆盖进入 `app_main` 之前就失败的情况，早期故障仍需串口恢复；未来再设计引导级回退。不修改 eFuse 或安全启动配置。

第一阶段返回页支持触摸返回和 BOOT 键返回，显示初始化失败时限时自动重启回主系统。共享系统 NVS 仅按现有驱动读取；模拟器不得自动擦除 NVS，游戏配置独立保存到 SD。

主系统进入模拟器时按现有逻辑刷白；模拟器返回时使用自身 MSG 行扫描刷白并等待完成，不调用 quality/DU4 等阅读波形。返回前等待 BOOT 释放，避免误入下载模式。启动时尚未释放的 BOOT/触摸不作为返回动作。模拟器入口还检查 factory 的布局和项目身份，避免只检查模拟器而忽略返回目标。

## 构建、烧录与验证

使用 IDF 6.1：先构建并烧录更新后的主系统/分区表，再构建和安装模拟器。主系统仍使用 `scripts/build-board.ps1`。模拟器使用 `scripts/build-emulator.ps1`；后续命令与验证记录随实现补齐。

```powershell
# COM5 按实际串口修改。首次需更新主系统及分区表，不需要整片擦除。
./scripts/build-board.ps1 -Board MyPaperS31 -Action build
./scripts/build-board.ps1 -Board MyPaperS31 -Action flash -Port COM5
./scripts/build-emulator.ps1 -Action build
./scripts/build-emulator.ps1 -Action flash -Port COM5
```

VS Code 任务增加 `Build S31 emulator`、`Flash S31 emulator`。入口位于系统主页第二页的“模拟器”图标；进入确认页后点“重启进入”。未安装正确镜像时显示安装提示，不允许重启。第一阶段验证成功后，只需更新模拟器镜像，无须再次烧录主系统或分区表。

安装脚本读分区表、写入并校验时使用 `--after no-reset-stub`，避免 esptool 的最终复位错误掩盖真实校验错误。只有写入校验命令成功后，才单独请求 USB Serial/JTAG 硬复位；此阶段串口断开仅提示手动复位，不误报写入失败。写入/校验失败则保留错误且不自动复位。硬件重启应松开 BOOT 后按 RESET 或断电重启，不用 BOOT 键代替 RESET。

模拟器的普通 flash/app-flash 目标也必须只包含 0x810000 的模拟器应用，不能携带主系统、引导程序或分区表。安装工具额外读取设备真实分区表，要求 factory/emulator/otadata 地址与大小匹配，核对本地镜像项目名、芯片及 4 MiB 上限后才写入；旧单固件布局拒绝安装并提示先烧录主系统。

模拟器的 `flash` 和 `monitor` 可在普通 PowerShell 中执行：脚本从 `build-s31-emulator/project_description.json` 和 `CMakeCache.txt` 自动取得构建时的 IDF 6.1 和 Python 路径，不要求当前终端已激活环境，也不会重新构建。环境被移动或构建产物缺失时会明确报错。可附加 `-DryRun` 只检查路径和打印命令，不连接设备。`build` / `reconfigure` 仍需先激活 IDF 6.1。

推荐始终用安装脚本，它会读设备真实布局；直接 `idf.py flash` 虽已限制只写模拟器地址，仍不负责确认设备已经更新分区表。主系统烧录清单包含主程序、引导程序、分区表和初始 otadata，不覆盖模拟器镜像或 NVS；之后主系统更新会恢复默认启动主系统。

IDF 自带 `app_check_size` 把当前镜像与所有应用分区比较，主系统约 4.9 MiB 因而会提示不适合 4 MiB 模拟器槽。这不是 factory 溢出。构建另外添加 `firmware_slot_check`：System 强制检查 factory 8 MiB，Emulator 强制检查 ota_0 4 MiB，真正超过各自预算会失败。保留 SDK 原通用检查，不修改安装目录的 IDF 文件。

验收：未安装镜像时能返回；安装后主系统→模拟器→主系统；模拟器中按复位回主系统；主系统设置和 SD 数据保留；错误镜像/旧分区表拒绝；两份镜像分别编译与烧录。新 UI 字符串加入简繁英词表，并检查/更新系统 TTF 子集。

## 第二阶段：S31 独立 GB 固件

### 显示通路

`PaperDisplay.cpp` 独占 LCD i80 和行扫描任务；不初始化 `M5.Display` 或 M5Unified，不实例化 `Panel_EPD_2D`，不链接 `my_waveform.c`，也不使用阅读器的刷新队列、转换统计、驱动帧缓存或动画预热。

沿用 Paperboy `msg/msg.c` 的结构：CPU1 逐行 DMA、24 MHz 请求像素时钟、两个行缓冲、帧边界交换游戏前后台缓冲。每两个子像素用一个状态字节保存目标颜色和两个计数；颜色改变时重置对应计数，连续驱动四个扫描场后输出 NOP。保持原作的三行分摊计算、两行流水线补偿及三倍缩放。

S31 面板为 1216×684。游戏原始 160×144，逻辑竖屏区域为 480×432，左上角 `(102,160)`；按面板旋转 3 映射至物理区域 `432×480 @ (160,102)`。四种灰阶采用原作的 0/1/2/3 个黑色子像素空间组合，不是 16 灰阶阅读波形。游戏窗口外持续输出 NOP。

菜单绘制只使用离屏 LGFX 1bpp sprite，实际刷新仍交给独立行扫描：8 场向白清除，再用 8 场黑色掩码绘制文字。静态界面完成后关闭屏幕偏压；游戏期间保持供电。TPS65185/TCA9555 引脚、-1.23 V VCOM 和关电顺序参考已验证的 S31 硬件，不能复制原作 S3 的电源引脚。

模拟器默认 RTOS tick 为 1 ms，主任务栈 16 KiB，独立配置在 `firmware/emulator/sdkconfig.defaults`。每约 100 ms 扫描边界让 IDLE1 运行一 tick，此时 OE 已关闭；不放宽/关闭看门狗。核心与扫描热点编译为 `-O3`。

| 缓冲 | 大小 | 存储位置 |
|---|---:|---|
| 游戏 1bpp 前后台缓冲 | 2×8640 B | SRAM |
| 两子像素驱动状态 | 34560 B | SRAM |
| 行 DMA | 2×320 B，另加驱动对齐 | SRAM/DMA |
| GB 工作 RAM / 显存 / LCD | 32768 / 16384 / 5760 B | SRAM |
| 核心结构 | 由核心 ABI 决定 | SRAM |
| 全屏离屏菜单 | 103968 B | PSRAM |
| ROM / 卡带 RAM / 临时存档 | 按实际大小 | PSRAM |

构建自动执行 `tools/check_emulator_isolation.py`，检查 ELF 中必须有独立扫描及 GB 核心符号，禁止出现阅读 EPD、M5 显示初始化、Wi-Fi 初始化及 USB Host 安装符号。

### ROM 与操作

- SD 卡目录：`/roms/`，即设备 `/sdcard/roms/`，不存在时创建。支持子文件夹和 `.gb` / `.gbc` 文件枚举。
- 当前使用原作同款 DMG 核心；支持普通 GB 及有 DMG 兼容模式的游戏，明确拒绝 CGB-only 游戏。后缀不是兼容性判断依据。
- ROM 为 32 KiB～4 MiB，检查实际长度、银行数、RAM 编码及头校验，再进入核心，避免原核心越界索引头部表。
- 目录逐级浏览，不常驻整张 SD 卡索引。每目录最多 1024 个项目/256 KiB 名称路径预算，超预算明确提示拆分目录，不静默漏项。
- 游戏页屏幕下方有方向、A/B、SELECT/START；支持两个触点组合。VOL+ / VOL- 分别作为 A/B；BOOT 或电源短按暂停/继续。触摸壳体 Home 调出菜单，前后键可作左右。
- 暂停菜单：继续、保存状态、读取状态、重启游戏、ROM 列表、返回主系统。保存失败时显示额外的明确放弃保存返回入口。
- 核心按约 59.7 Hz 的时钟预算运行，扫描独立消费最新画面；扫描慢时丢弃中间显示帧，不跳过 GB CPU 帧来制造速度。实际扫描帧率以 `EMU_SCAN` 日志为准，尚未宣称实机达到 60 fps。

可生成不包含商业游戏数据的自制测试 ROM：

```powershell
python tools/make_emulator_test_rom.py
# 输出 tmp/emulator/S31-Demo.gb，复制到 SD 卡 /roms/。
# 画面为自动滚动的四灰阶条纹；按 A 反转灰阶，可验证输入与存档。
```

### 存档及限制

卡带 SRAM 在打开时自动恢复，暂停/退出时保存；游戏帧循环不写 SD。暂停菜单另提供一个手动状态槽，不自动载入状态。分别保存在 ROM 同目录，保留完整 ROM 文件名并追加 `.s31.sav` / `.s31.state`，避免与原作存档相互覆盖。

文件包含版本、ROM 全文件 CRC32、类型、精确长度及负载 CRC32；状态还经过核心自身的版本/结构大小/字节序检查。写入 `.tmp`、flush/fsync/close 成功后才安装；保留上一代 `.bak`，主文件损坏或中断时可回退。无法验证的存档不导入内存。

当前离线关机期间卡带 RTC 追时、三语言游戏菜单及完整电量/待机功能尚未接入。卡带 RTC 的寄存器会存档，开机期间按单调时钟推进。菜单暂用英文，中文文件名由随 M5GFX 附带的 efontCN 位图显示，不使用主系统 TTF/字形池，所以本轮无需重新生成系统 TTF 子集。

## 第三阶段：S31 游戏外放

沿用 Paperboy 的 MiniGB APU，接入 GB 四声道寄存器读写。每帧按 70224/4194304
秒累计音频采样，32768 Hz 的输出交替生成 548/549 个双声道采样帧；不能直接调用
原作固定 704 个采样的回调，否则会发生音速/队列漂移。即时存档追加 APU 状态和
采样余数，同时允许读取旧静音固件的核心存档，后者重置 APU 后由游戏重新写寄存器。

`GameAudioOutput` 是独立输出实现，不链接主系统 audio_radio、GMF、Wi-Fi 或 USB Host。
APU 在游戏任务生成 PCM，流式重采样/混为单声道后提交 4096 采样的有界 FIFO；
独立 CPU0 音频任务以 I2S DMA 消费，并将单声道复制到左右声道。队列满时丢块，
游戏任务不等待 I2S。显示继续使用已验证的独立 MSG 行扫描，CPU1 通路不变。

BH1098G 沿用主系统已验证的 UART1 TX39/RX38、115200、RX=2/MODE=1 初始化；
P14 为原项目的 VOUT/BT-PA 供电控制，与 TPS 可访问状态有关；模拟器启动时恢复并保持该供电，不能由音频清理单独关闭。P04 控制 PA，TCA 输出读改写由互斥锁保护，不覆盖屏幕控制引脚。
I2S0 BCLK42/WS43/DOUT44/DIN45，32-bit stereo slots，PCM 在高16位。
通常 BH1098G 提供 16 kHz 主时钟，先测量并验证；仅两根时钟都高阻时退回 MCU 主机，
不驱动已有主时钟。启动过程在后台完成，不让 ROM 浏览等待数秒。

初始音量读取主系统 `audio_out/spk_volume`（只读、默认30%），本次会话可在暂停菜单
切换 Sound ON/OFF、用 -/+ 调音量。物理 VOL+/- 保持游戏 A/B，不改变已验证的按键映射。
暂停、换游戏及返回主系统前先静音 PA、清队列与 DMA；退出销毁 I2S/UART，保留共享 P14/VOUT 供主系统接管。

返回主系统自动重启，不需要按 BOOT。刷白前检查 BOOT 是否松开，低电平时显示释放提示；3 秒仍未释放则恢复菜单，允许释放后重试。如果拆卸资源期间又按住 BOOT，则显示提示并等到松开再重启，避免进入下载模式。音频退出最多等待 2 秒；超时仅静音 PA，保留工作任务正在使用的缓冲区和同步对象，由后续重启回收，不强删任务或提前释放内存。模拟器 I/O 输出互斥锁最多等待 100 ms，避免退出静音也无限等待。退出日志标记保存、刷白、音频关闭、SD 卸载与最终重启，便于定位停留阶段。

`tools/test_emulator_shutdown.py` 提取生产音频退出方法，验证任务超时不释放正在使用的资源、迟到完成可以再次回收、重复关闭和部分初始化失败均无需无限等待。

主系统从模拟器重启回来时必须恢复扩展口 P14（VOUT/BT-PA 供电）和 P05，不能仅保留原来的输出锁存值：旧模拟器音频退出会关闭 P14，而 MCU 软件复位不会复位 TCA，实机记录显示重启成功后 TPS 的首次寄存器写入失败。模拟器已改为在初始化时恢复 P14，音频清理不再关闭该共享电源。主系统 `Bus_EPD_S31::init()` 也按原项目将 P14 配成输出并拉高，释放 P12 触摸复位后等待 80 ms，再检查电源输出和方向寄存器。恢复失败不启动扫描。TPS（0x68）I2C 失败也输出实际 IDF 错误码，避免只看到上层的通用失败。更新模拟器可消除退出时关闭该轨的行为；主系统的额外启动保护需要更新主系统镜像。两者均不改变独立模拟器的显示通路。
外放初始化失败仍可静音玩游戏。Type-C 耳机和蓝牙耳机不属于本阶段。

音频新增 SRAM 主要为 8 KiB FIFO、TX/RX 各约6 KiB DMA及6 KiB任务栈，转换临时区等
其余按对象/缓冲实际分配；不能将这些内存误算成几 MiB。两份固件启动都按共享的
CX25601N 策略恢复正常充电，先关闭遗留 OTG 再启用充电，不改充电限制参数。

```powershell
python tools/make_emulator_test_rom.py --audio --output tmp/emulator/S31-Audio-Demo.gb
# 放到 SD /roms/：约440 Hz，按 A 约880 Hz；使用自制 ROM，无商业游戏数据。
```
