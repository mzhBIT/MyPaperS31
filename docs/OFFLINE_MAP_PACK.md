# 离线地图：PC 转换工具与 MPM v1/v2 分块地图集

已实现 PC 打包/校验/预览及固件离线显示、平移、缩放。输入是 QGIS 导出的
256×256 XYZ PNG（`z/x/y.png`），不读取 SHP 或 PBF。保留地图上的 OSM
来源标识；发布数据包时需遵守源数据许可，固件显示 OpenStreetMap contributors 归属信息。

## 设备测试入口

将 `tmp/map/hangzhou-test.mpm` 复制到 SD 卡（例如 `/sdcard/maps/hangzhou-test.mpm`）。
在“设置 → 应用配置 → 地图”中选择离线地图源并选择地图包，然后打开主页地图应用。
单包首次使用包中心和最高缩放层级；地图集首次使用概览包中心和概览最高级，之后保存独立的离线经纬度/缩放位置。在线高德的 GCJ-02
位置和离线 WGS84 位置不混用。离线模式不要求 API Key，也不会初始化 Wi-Fi 或 4G。

首版不读取 PNG：从包内读取原始 4bpp 瓦片并校验 CRC，24 张瓦片按 LRU 缓存。
684×1216 下两张独立拼接帧占 831744 字节，瓦片缓存最多 786432 字节，另加索引（每瓦片
32 字节）；这些大块数据均位于 PSRAM。索引最多 131072 条，当前 FAT stdio 限制单包小于
2 GiB。超过限制请按地区分包，不能直接把全省所有高等级瓦片塞进一个包。

拼接仅在 EPD 空闲时执行；整帧完成后才导入显示缓冲并执行 Quality 刷新，不修改波形或扫描时序。
缺图、越界、CRC 错误时保留上一幅完成帧并提示。只允许切换包内实际存在的缩放层级。
日志 `offline viewport` 包含读卡瓦片数、缓存命中数和拼接耗时；初版在主线程同步拼接，
需要实机验证触摸响应和读卡速度，暂不引入异步 PSRAM 读写。

## 使用

### 全省自动分块（v2 纯色压缩 + 自动选包）

源瓦片目录为 `F:\Map\tiles`。以下命令只读取源数据，所有计划/索引/输出写到独立目录。
生成期间可以仅扫描计划，不解码、不打包；该结果只是当前快照，不能当作导出完成验证：

```powershell
python tools/split_offline_map.py --tiles F:/Map/tiles --output tmp/map/zhejiang-pack-plan --plan-only
```

QGIS 完全生成后执行（Extent 顺序与 QGIS 相同：xmin,xmax,ymin,ymax）：

```powershell
python tools/split_offline_map.py --tiles F:/Map/tiles --output tmp/map/zhejiang-v2-packs --extent-3857 13134748.1430 13630841.8930 3138680.6590 3714943.1590
python tools/test_split_offline_map.py
```

默认 Z8～Z13 为概览包（不受详细包 512 MiB 目标限制，但仍需小于固件 2 GiB 上限）；
Z14～Z16 以 Z14 的 16×16 瓦片为核心区域，各边扩展 3 张 Z14 瓦片作为重叠。
单边 768 像素大于屏幕半高 608 像素，避免一张重叠瓦片不足以覆盖跨区视口。
完整详细块未压缩约 318 MiB；超过 512 MiB 会递归细分。重叠会增加总磁盘占用。
SQLite 目录索引避免同时将百万条文件路径加载到内存。缺层级、矩形内部缺图、未覆盖
指定 Extent 时拒绝正式打包；源文件变化时也拒绝确认完成。

逐包校验完成后保存 `.done.json` 收据，重新执行相同命令会检查收据和 CRC 后跳过完成包。
来源、尺寸或修改时间变化时不自动覆盖旧包，要求使用新的输出目录。中断若留下无收据的
单包或 `.tmp`，需要人工核对后处理，脚本不会盲目覆盖。全部成功才写 `manifest.json`。

默认输出 MPM v2：纯色瓦片只记录灰度，不存 32 KiB 像素；任何纯黑、纯白、纯灰都保留
原值，绝不将纯黑瓦片作为无效区域删除。其余瓦片使用与 v1 相同的 4bpp 数据。
量化规则不变；可选 NumPy 加速与原 Python 算法逐字节一致，默认 8 个线程、最多 64 张
瓦片的有界批次，不把全省 PNG 加载到内存。`--version 1` 可生成旧格式，`--workers 1` 可串行。

全部完成后生成 `catalog.mpc` 和 `manifest.json`。将 **所有 `.mpm` 与 `catalog.mpc`** 放在
SD 卡同一目录，在设备地图包选择器选择 **`catalog.mpc`**，无需逐个选地区。
JSON 是供 PC 查看来源、范围与实际体积的清单；固件读取小型二进制目录，按当前 zoom 和
中心坐标选核心区，必要时尝试重叠邻区。只打开当前包，区域索引放 PSRAM，不加载全省索引。
跨包时先在独立 reader 中完成读取和整帧拼接，成功后交换所有权；缺失/损坏包不会覆盖
已有完整帧。切包时会短暂保留两个 reader（各有帧、索引及按需瓦片缓存）。
固件兼容已验证的 v1 概览包与手动单包选择；v2 及 catalog 需要更新固件后使用。

依赖 Python 3 与 Pillow。项目电脑已有 `D:\Software\conda\python.exe` 和 Pillow。

```powershell
python tools/build_offline_map.py build --tiles tmp/map/tiles --output tmp/map/hangzhou-test.mpm --zooms 14,15,16 --bbox 120.06 30.30 120.14 30.38
python tools/build_offline_map.py verify tmp/map/hangzhou-test.mpm
python tools/build_offline_map.py preview tmp/map/hangzhou-test.mpm --zoom 16 --center 120.10 30.34 --output tmp/map/hangzhou-preview-z16.png
python tools/test_offline_map.py
```

`--bbox` 顺序为西、南、东、北，单位 WGS84 经纬度，不是高德 GCJ-02。
范围按相交瓦片选择，不裁掉边缘瓦片。未给 bbox 会打包指定层级的所有图片。
默认要求 bbox 对应瓦片齐全，QGIS 未完成时缺图会报错；`--allow-missing`
仅供有意生成稀疏包时使用。不要为了绕过正在生成的文件而开启该参数。
默认不覆盖已有包，确认重做时使用 `--force`。打包使用独占临时文件，全部
图片解码及 CRC 校验通过后才替换输出。生成时不要让 QGIS 重写同一批输入。

转换先将透明像素合成到白底，再转亮度并舍入量化到 16 灰阶。不套用在线地图
黑阈值 100 的 LUT，避免彩色道路在首次试验中被压黑。最左像素在字节高半部，
0 为黑、15 为白。原始 256×256 瓦片占 32768 字节，不压缩；这是初版格式。
预览直接读取地图包中的像素，并按标准 XYZ 原生像素比例拼接成 684×1216，
缺瓦片报错而非默默填白。它不模拟 EPD 实际灰阶或在线地图的 2 倍放大策略。

## 二进制格式（全部整数/浮点采用 little-endian）

固定头部 96 字节，结构 `<8sHHIIIII4dQQII` 占 88 字节，末尾补零 8 字节：

| 偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | char[8] | `MPMAP001` |
| 8 | uint16 | 版本 1 或 2 |
| 10 | uint16 | 头部大小 96 |
| 12 | uint32 | 瓦片边长 256 |
| 16 | uint32 | 瓦片总数 |
| 20 / 24 | uint32 | 最小 / 最大 zoom |
| 28 | uint32 | flags=1：WGS84 + XYZ/Web Mercator |
| 32 / 40 / 48 / 56 | float64 | 所有实际瓦片的外包范围：西、南、东、北 |
| 64 / 72 | uint64 | 索引 / 像素数据起始偏移 |
| 80 | uint32 | 索引条目大小 32 |
| 84 | uint32 | 整个索引 CRC32 |
| 88 | byte[8] | 保留，零 |

每条索引 32 字节：`<BBHIIQIII`。

| 偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | uint8 | zoom |
| 1 | uint8 | 编码 0：未压缩灰阶 4bpp |
| 2 | uint16 | 保留，零 |
| 4 / 8 | uint32 | x / y |
| 12 | uint64 | 像素数据绝对文件偏移 |
| 20 | uint32 | 数据长度，固定 32768 |
| 24 | uint32 | 当前瓦片像素 CRC32 |
| 28 | uint32 | 保留，零 |

索引按 `(zoom,x,y)` 严格递增，适合固件二分查找。外包范围不保证范围内所有
层级都存在瓦片（允许缺图或原始导出层级范围不一致时）；固件须实际查索引。
CRC 使用标准 zlib/IEEE CRC32。设备端不能直接映射 C struct，避免未对齐和
编译器填充差异，须逐字段读取；文件偏移使用 64 位并检查平台 seek 支持。

### v2 扩展

编码 0 与 v1 一致，但原始数据偏移按实际存储的原始瓦片连续递增，不含纯色瓦片。
编码 1 为纯色：偏移 2 的 uint16 存储灰度 0～15，数据偏移与长度均为 0；CRC 仍是
展开后 32768 字节像素数据的 CRC，其他保留位仍必须为零。文件尾必须恰好等于原始数据尾。
设备先验证索引 CRC 和所有条目的结构，访问瓦片时验证其展开后像素 CRC。

### MPC 目录格式

头部 32 字节：`<8sHHIIIII`，依次为 `MPCAT001`、版本 1、头长 32、记录长 136、
包数、目录记录 CRC32、flags=1、保留 0。每条记录 `<64sI4x8d`：ASCII 同目录包文件名
（64 字节、零结尾）、zoom 位掩码、保留 4 字节、核心范围与覆盖范围各 4 个 double
（西、南、东、北）。拒绝路径分隔符、`..` 和非 `.mpm` 文件名。概览包为第一条。
目录最多 4096 包；设备只保存目录元数据，不读取未使用包的索引或像素。

## 固件流水线

地图源选择 → 区域包元数据/索引检查 → 当前视口瓦片读取与缓存 → 独立 4bpp
帧拼接 → EPD 空闲后导入 → Quality 刷新。此阶段不修改波形或扫描时序。
在线 GCJ-02 和离线 WGS84 视口分开存储或显式转换，不能直接叠加坐标。

## 按行政边界筛选现有包（无需重新转换）

`tools/select_offline_map_region.py` 读取 WGS84 行政区 SHP/SHX/DBF，按真实多边形与
区域包 **核心范围** 相交选择，包含边界接触；支持凹多边形、多岛与孔洞，不是仅比较外接矩形。
保留相交包内全部地图及既有屏幕边缘重叠。概览包保留浙江范围，不做重新解码或裁剪。
输出是独立文件复制，不是硬链接，不修改原图集；复制完成且 CRC 校验通过后发布新目录索引。
新目录的首次概览中心改为选定行政区范围中心，不改变概览包像素或固件。

```powershell
python tools/select_offline_map_region.py --source tmp/map/zhejiang-v2-packs --output tmp/map/hangzhou-region-packs --admin-shp Assets/zhejiang-260908-free.shp/gis_osm_adminareas_a_free_1.shp --name 杭州市
```

可加 `--plan-only` 只统计选包和体积；正式输出必须使用新目录，不自动覆盖已有地图集。
本地边界记录为 OSM `3221112` / `admin_level5` / `杭州市`，包含市行政区而非仅城区。

杭州筛选结果：`tmp/map/hangzhou-region-packs` 共 29 个包（28 个详细包 + 1 个原浙江
概览包），合计 7,061,145,920 字节（6.58 GiB）；不是外接矩形筛出的 49 个包/9.85 GiB。
已逐包复制及 CRC 校验，并用原生 reader 验证正式杭州目录的跨区连续性与淳安/建德 Z16。
不需要改固件或重新烧录，使用已支持 MPM v2 和 catalog 的版本即可。
