# S31 触摸采样与识别

S31 按 `main/boards/MyPaperS31/Pins.h` 的定义使用 GPIO5 作为 FT6336U INT 引脚。本次按该接线实现，实际电气接线与中断波形仍需实板确认。P4 保留原轮询采样入口；Windows/macOS 使用同一套 S31 源码。

## 数据流

GPIO5 双边沿中断只通知 `s31_touch` 任务，不在 ISR 中操作 I2C、屏幕或应用。任务直接读取触摸控制器，避免经过显示绘图事务；I2C 访问仍使用现有总线互斥。

按住时每 tick 采样（当前 100Hz 配置下约 10ms）；空闲时由中断立即唤醒，另保留 50ms 轮询兜底。移动和按下/松开入队，静止按住每 20ms 留一个样本。128 个样本带采集时间戳，UI 绘制时仍可采集。主线程负责坐标转换、边框触摸按键、手势识别与页面调用；新样本可唤醒主循环的空闲等待。

FT6336U 在 S31 路径单次读取两个触点所需的 11 字节寄存器帧，不再反复读取直到连续坐标相等。INT 电平仅作为采样提示，不直接当作松手状态。I2C 失败或异常触点数与正常无触摸分别处理。

## 识别与生命周期

- 点击在松手时生成；移动不超过 20px 且持续时间小于 600ms。
- 长按阈值 600ms；若松手样本首次跨过阈值，也能补发长按。一次接触只产生一次长按或滑动，滑块认领接触后抑制手势。
- 页面代次在新页面绘制前发布。旧样本和未松开的旧接触被取消，新页面绘制期间的新点击可保留。
- I2C 错误、样本队列溢出、超过 1500ms 的过期样本取消当前接触，重新采样，等松手后恢复，避免用不完整轨迹合成点击。
- 待机前关闭 GPIO5 中断并等待采样任务退出 I2C；唤醒后清理缓存、恢复任务，吞掉唤醒期间仍按住的接触。
- IRQ 注册失败时保留独立任务轮询；任务内存分配失败时回退到主线程轮询，并记录日志。

## 验证

运行 `python3 tools/test_s31_touch.py`，使用实际识别器源码和 S31 解码器分支回放：UI 阻塞期间的点击、350～599ms 点击、长按、连续点击、滑动、滑块认领、跨页面接触、I2C 错误、队列溢出、过期样本、唤醒、边框键和时钟回绕。

运行 `bash scripts/build-s31.sh` 构建固件。实机启动日志应出现 `S31_TOUCH: GPIO5 IRQ=1`；可在刷屏时快速点击、滑动，检查待机唤醒后的第一次点击和边框按键。主页面原有的“先选中图标，再次点击打开”行为仍保留。
