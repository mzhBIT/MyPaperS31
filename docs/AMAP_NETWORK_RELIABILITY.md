# 高德 JSON 查询的连接可靠性

2026-10-03：搜索地点、IP/逆地理定位和路线规划共用 `AmapClient::fetch_json`。
这些在线查询不依赖当前地图层级；离线地图无需先切到 Z17 来预热网络。

- 每次连接及等待响应头的 HTTP 超时从 3 秒提高至 8 秒。
- 最多两次尝试。只有传输失败才重建客户端重试一次；HTTP 非 200、API
  业务错误、内存分配失败和响应超过容量限制不重试。
- 重试前至少等待 500 ms，并继续使用全局请求间隔控制。等待期间每 10 ms
  检查取消状态；正在进行的阻塞网络调用则在其返回后检查取消。
- 每次尝试仍有 15 秒的读取循环时间预算，单次读取超时为 1 秒；此预算
  在网络调用之间检查，不是可强制中断网络调用的硬截止时间。
- 响应缓冲区仍在 PSRAM 中，仅分配一次。重试清空有效字节数，不拼接失败
  请求的残留数据；客户端释放后才解析响应和发布 UI 结果。
- 日志分别记录 `open`（DNS/TCP/TLS 及发送请求）、`headers`、`read`、
  每次传输总时间及包含重试等待的查询总时间。日志不输出 URL、Key 或搜索词。

不改变在线地图下载、地图比例尺、Wi-Fi 生命周期或 EPD 刷新逻辑。
设备验证应覆盖：停留离线 Z16 直接搜索、定位、路线规划；断网超时后返回；
查询期间取消；确认失败最多重试一次。首次请求失败的具体网络阶段仍需结合
新增时间日志判断，不能仅凭“切到 Z17 后成功”认定根因。

## 地图缩放性能日志

- `AMAP_HTTP: static map timing`：每次下载的 open、等待响应头、累计网络
  read、累计 SD fwrite、SD fclose、首次正文读出时间、最长单次 read、
  read 调用次数和 EAGAIN 次数。耗时单位为微秒；first_byte=-1 表示未读到正文。
  read 不包含后续 SD 写入，open 包含 DNS/TCP/TLS 及请求发送，不能当作纯 TLS 时间。
- `MAP: fetch timing`：网络连接准备以及下载与 TLS 清理的耗时。
- `MAP_CACHE: store timing`：目录清理、图片复制及 CRC、目录扫描、LRU
  淘汰、图片和元数据提交的耗时。成功提交后才输出这一条汇总。
- `MAP: commit timing`：后台完成到主循环接收的 dispatch 延迟、准备、
  缓存存储、NVS 保存和主循环提交总耗时。仅成功采用结果时输出。
- `MAP: draw timing`：绘制设置、清屏、图片处理及导入、界面叠加、刷新
  提交和 endWrite 的耗时，不包含后台 EPD 扫描；扫描仍查看原 EPD 日志。

只在阶段完成后输出汇总，不在网络读取、CRC 或像素循环内打印日志。
添加计时本身不改变任务、缓存、NVS、图片处理或 EPD 驱动策略。

## 缓存提交优化

设备日志确认每次提交约 1.17 秒，其中目录清理约 560 ms、扫描约 290 ms、
二次图片复制/CRC 约 160 ms。现改为：

- 每个 MapCache 实例首次访问清理残留并建立内存索引，后续 lookup/store 不
  重复扫描目录；LRU 和容量计算在内存进行，年龄仍持久化到原元数据格式。
- 地图 on_show 重置索引，以兼容从设置清理缓存后返回；新建实例也重新扫描。
  缓存仅在原主循环空闲阶段操作，不增加异步 SD/PSRAM 任务。
- HTTP 下载每个成功写入的数据块顺便累计 IEEE CRC32。完整响应、成功
  fclose 和图片格式检查后才发布 CRC；重试重置累计状态。
- store_download 检查已关闭临时文件的长度，用 rename 直接提交同一 SD
  文件，不再次复制或读取 CRC。提交失败时尽量恢复临时文件，供现有单图回退。
- 命中缓存仍重新检查元数据、文件长度和 CRC，因此没有取消损坏检测。
  启动恢复、容量限制、LRU 淘汰、非缓存文件保护和元数据提交标记保留。
- 新日志 `index ready` 只在索引重建时出现；`store timing` 中 index、lru
  是新的索引/LRU开销，adopt=1 表示直接接管下载文件。

主机测试覆盖 CRC 标准向量及分块累计、直接接管源文件、长度/容量拒绝时
保留源文件、元数据写入失败恢复、重开恢复、CRC 损坏、LRU 和安全清理。
P4 编译通过；实际节省时间需设备日志验证。首次进入仍需一次目录扫描；
SD 下载小块写入、NVS 保存和 EPD 刷新未更改。

## 返回主页的残影清理

MapActivity 实际销毁时向主页提交一次性 Quality 请求。主页下一次 on_show
恢复时，用 Quality 绘制完整主页并立即消费请求；后续主页滑动、选中和页眉
更新仍使用 Text。地图内部返回搜索/路线页面不会触发此请求。
验证日志为 `HOME: one-shot Quality refresh after leaving map`。

## 下载合并写入及省去冗余清屏

- 静态地图临时文件使用 32 KiB PSRAM stdio 全缓冲，合并原有小块 fwrite。
  HTTP 读取块和取消检查不变，缓冲在所有 fclose 返回后才释放。分配或
  setvbuf 失败时使用原缓冲策略，不影响下载功能。
- fclose 的尾部刷盘错误仍判定下载失败，CRC 只随成功 fwrite 累计，只有
  完整响应、成功关闭文件后才提交结果。性能评估比较 sd_write+sd_close，
  不能仅看到 fwrite 变快就认定整体刷盘变快。sd_buffer=32768 表示启用。
- PNG 在绘制阶段先完成灰度帧准备；在线/离线的完整原生灰度帧导入成功时
  已覆盖全部像素，不再额外清白屏。失败时仍清屏后走原图绘制回退，不跳过
  页眉、控件和路线绘制，也不改变 EPD 目标快照和刷新策略。
- draw timing 的 image 包含预处理、导入和回退；clear_skipped=1 表示
  完整覆盖成功，clear 应接近零。期望省去此前约 48 ms 清屏，设备验证为准。

P4 编译验证；需要设备检查在线/离线缩放、PNG失败回退及画面完整性。
