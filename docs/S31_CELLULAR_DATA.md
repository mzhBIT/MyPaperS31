# MyPaperS31 4G 数据通信

NT26 为可选硬件：正常开机时先探测，确认基带 AT 响应后，设置中才显示 4G 选择项及 4G/SIM 设置；未检测到时隐藏两项，并收拢布局和触摸/按键区域。无 SIM、SIM 未激活或没有信号不等同于无基带，仍保留设置入口。固定无基带版本可关闭 `CONFIG_MYPAPER_S31_CELLULAR`，移除 NT26 实现。摄像头使用独立开关，见 [可选硬件说明](S31_CAMERA.md)。

如果上次保存的网络选择是 4G，本次启动没有检测到基带，会在内存中切回 Wi-Fi，防止应用等待不存在的硬件；不改写 NVS 中的原偏好，避免一次探测失败永久丢失选择。重新开机重新探测，不执行运行期间的热插拔扫描。USB U 盘模式跳过探测。

S31 使用 NT26 的 UART 以太网协议。它与 P4 的 ML307A USB/RNDIS 后端分别实现，应用通过现有网络选择接口使用当前连接。

## 硬件与依赖

| 信号 | 配置 |
| --- | --- |
| UART | UART2，2,000,000 baud，8N1 |
| 主控 TX / RX | GPIO58 / GPIO59 |
| MRDY / SRDY | GPIO60 / GPIO3，官方握手协议 |
| 电源 | TCA P1.4，与 BH1098G、功放共享 |
| 复位 | TCA P1.2，与触摸共享，运行时保持高 |
| 数据接口 | `iot_eth` → `esp_netif` / lwIP，接口名 `S31_NT26` |
| 控制台 | USB Serial/JTAG；UART0 不得再占用 GPIO58/59 |

驱动来自 Metalio-E-INK4-Plus：`main/boards/common/board/uart_eth_modem.*`。保留原作者与 Apache-2.0 标注；依赖固定在 `third_party/s31/uart-uhci`（0.2.2）和 `third_party/s31/iot_eth`（0.1.0），使用官方工程中的版本，不在线解析依赖。

## 用户入口

设置 → 网络：选择 Wi-Fi 或 4G；选择 4G 后关闭原 Wi-Fi 接口并异步启动 NT26。网络 → 4G 设置：查看状态、选择外置 SIM / 内置 SIM、点击重试。

切换网络不重启系统。旧网络先完成任务与接口清理，新网络再启动；已有 HTTP、下载或音频连接需要重新连接，无法跨接口无缝迁移。4G 注册通常比保存的 Wi-Fi 连接慢，应用请求可能先超时；可在 4G 设置等待连接成功后再进入应用。

首次不强制改写模组的卡槽。查询实际卡槽：0 外置，1 内置。用户选择另一张卡时，先停止旧驱动，再在新初始化流程中执行：

1. `AT+ECSIMCFG?` 查询当前选择。
2. 不同时执行 `AT+CFUN=0`，等待 500 ms。
3. `AT+ECSIMCFG=SimSlot,0/1`，等待 500 ms。
4. `AT+CFUN=1`，查询并核对实际卡槽。
5. SIM 就绪、注册、UART 协议握手、DHCP。

仅在模组确认卡槽后将偏好保存到 `cellular_s31/sim_slot`。恢复默认设置会清除该偏好，下一次启动重新查询模组当前选择。内置卡的开通、套餐及运营商服务由卡的提供方管理。

## 生命周期与资源

开机探测在共享电源/I²C 初始化之后、主页和网络工作任务启动之前运行。恢复共享电源后留出启动等待，创建临时 UART2/UHCI 及传输任务，沿用 NT26 帧协议和 MRDY/SRDY 握手，仅发送 `AT`，尝试 2 Mbps / 3 Mbps。不执行卡槽查询或切换、CFUN、模组持久配置、注册、DHCP，也不创建网络接口或修改默认路由。结束后等待任务退出并释放 UART/UHCI/DMA 和队列，MRDY 保持空闲高电平；不复位触摸，不切断共享音频电源。未安装模组时 SRDY 输入使用弱上拉，避免悬空产生中断。只有用户选择 4G 时才启动完整数据会话。

`CellularS31.cpp` 的单一工作任务拥有模组对象。应用和 UI 只提交启动、停止、切卡请求，查询内存中的状态快照；不在 UI 绘制时发送 AT。停止请求立即使旧回调失效，并等待实际 DMA、任务、网络接口退出；超时不得释放仍被使用的对象。

只有 DHCP 获得有效地址后才标记在线、设置默认路由并触发开机单次网络校时。SIM 缺失或注册被拒绝时保留 AT 通道，允许切换到另一张 SIM。状态栏用黑色 4G 表示在线，灰色表示正在连接或失败；Wi-Fi 模式仍使用现有图标。

待机/关机先暂停新启动并停止 NT26 任务，释放 UHCI 与 PM 锁；唤醒后按网络偏好恢复。运行时切换不拉低 P12/P14，避免复位触摸或中断音频。启动时使用读改写恢复共享电源，只对新拉高的电源等待 1 秒。

内部 SRAM 用于 UART DMA RX 池（4×1600 字节）、FreeRTOS 对象和任务栈；普通字符串及帧分配沿用 S31 的 PSRAM 优先策略。网络选中 4G 后，跨应用保持注册；Wi-Fi 省电配置只作用于 Wi-Fi。收音机使用当前默认网络接口处理 DNS，不对 4G 请求调用 Wi-Fi 电源设置。

## 实机验证

1. 烧录 S31 主系统后，检查 `CELLULAR_S31: boot probe`：有基带时 `present=1`，网络设置出现 4G 和 SIM 选项；无基带时 `present=0`，两项隐藏，按键不能选中隐藏项。开机探测结束后不应创建 4G 网络接口；进入设置选择 4G 后才应看到完整 `iot_eth` 初始化。
2. 分别选择内置/外置 SIM，检查实际卡槽、`CPIN`、注册与获得 IP。没有外置卡时应能看到 SIM 未就绪，并能切回内置卡。
3. 在线后测试 RSS、DeepSeek、地图、微信读书和收音机，确认没有 Wi-Fi 连接也能访问网络。
4. 多次 Wi-Fi → 4G → Wi-Fi 切换，确认系统不重启、旧接口任务退出、每次请求使用新默认路由。
5. 在搜网、已连接和音频播放后的状态分别测试待机/唤醒、关机、切模拟器，确认不会遗留 UHCI、GPIO 中断或音频电源异常。
6. 比较重复切换前后的内部 SRAM/PSRAM，确认模组资源释放后没有持续下降。
7. 保存 4G 偏好后在无基带的设备上启动，确认应用转用 Wi-Fi；重新关机安装基带后启动，确认菜单恢复。仅拔除外置 SIM 不应隐藏 4G。USB U 盘模式不应出现基带探测日志。

PC 编译仅能验证链接与配置；SIM 开通、模组版本兼容、射频连接以及反复切换稳定性必须通过实机验收。
