# 独立下一页像素缓存（第一阶段）

## 范围

当前启用 2D EPD 后端，覆盖本地重排、微信读书、TXT 和 RSS 阅读。
包含横排/竖排、合成粗斜体、ruby、行内批注、链接脚注标记、空白、分隔线、
阅读背景，以及至多一张图片的页面。多图片页、开启抖动
仍保留原有绘制路径；RSS 必须等待当前图片下载任务结束后再准备离屏页。
重排阅读器开关位于 `EpubReaderActivity.cpp` 的
`READER_PREFETCH_FRAMEBUFFER_ENABLED`，可关闭作同页 A/B 测试。

## 内存与绘图

新增 `ReaderPageBuffer`，1216×684 或 684×1216 下均为 415872 字节 PSRAM。
它拥有自己的 MemoryPanel，没有 USB、EPD 总线、任务、波形或电源操作。
复用 `Panel_EPD` 的像素绘制与灰度量化，绘图接口为灰度 8bit，实际存储为
高半字节优先的灰度 4bit。不要替换成普通 4bit Sprite：二者量化规则不同。
白底用 memset 初始化，不逐像素清屏。不得复制字形池指针作为页面内容。

第二阶段：MemoryPanel 使用真实面板的物理宽高、offset_rotation，以及
当前屏幕 rotation。调用方仍按逻辑坐标绘制，但每个像素直接落在物理方向
的 Buffer 中，不在点击翻页时做整页转置。内存仍为 415872 字节。

## 调度与提交

活动主线程执行 Layout → Glyph → Image → Framebuffer → Ready。
只有 `displayBusy()==false` 时准备下一阶段；Framebuffer 每次 loop 绘制
一个 PageItem，再返回事件循环，不新建线程，也不与 EPD 扫描并行。
这是提前计算，不是省去计算；用户快速连翻时允许缓存未命中。

缓存只在完整绘制后公布 Ready。章节/页号、布局签名、屏幕尺寸、旋转、
下划线设置及背景/抖动/模式资格均检查。设置重排或目标页变化释放缓存。
跨章节采用预取的目标 pages，消费时移动布局但保留像素缓存至导入完成。
页眉不缓存，导入后按实际当前章节绘制。

前台 redraw 在写入绘图 Buffer 前等待 EPD 完成，以免提交队列尚未快照时
覆盖源图。缓存通过新增 writePhysicalGrayscale4 导入，该接口校验物理尺寸、
屏幕旋转、内存布局、无偏移及 EPD 空闲后，只 memcpy 到绘图 Buffer，
并标记全屏修改范围。不修改 physical、target、波形、相位数或 DMA。
原 writeNativeGrayscale4 和图片矩形导入仍保持原样。导入失败走普通绘制。

## 验证

日志：`prefetch framebuffer ready ... packed_bpp=4 render=... us`、
`redraw framebuffer hit ... native=1`、`redraw timing: path=framebuffer`。
物理直拷新增 `physical 4bpp import: bytes=415872 rotation=3 copy=... us`。
命中后 clear/content 应为 0，import 包含原生导入与动态页眉时间。
需要硬件验证：同一文字页的普通绘制/缓存导入、中文英文两端对齐、下划线、
合成字形、跨章节、连续快翻、关闭页眉、设置变更、内存分配失败回退、
图片页回退和 DU4/Quality/HD。重点观察是否出现白膜或累积残影。
第一阶段用户已确认画面正常，日志旋转导入约 31ms，redraw 约 53ms。
第二阶段用户确认画面正常，物理直拷约 6.9ms，redraw 约 28.9ms。
第三阶段图片整页缓存用户确认正常；尚无逐像素比较结论。

## 扩展接入与返回页缓存（2026-10-03）

- 竖排每轮只绘制一列，游标记录右边界；横排记录纵坐标。正文、ruby 和
  批注仍使用原 TextRenderer，不新建小字号字形池。脚注弹窗不缓存，前台叠加。
- 背景先合成到独立页 Buffer，动态页眉不缓存。更改布局、字体、下划线、
  背景或公共评论开关时，通过既有设置重排路径清空缓存。
- 微信读书取消整页缓存排除；仅复用已经取得的正文/划线范围，不改变
  评论下载或网络进度上报协议。网络章节读取失败仍走原回退路径。
- TXT 预读下一页布局、准备字形，然后按行/列绘制；消费时使用同一份
  TxtPage，不重复解析。返回设置或提交设置时清空缓存。
- RSS 将正文绘制提取为任意 gfx 目标，单张图片使用离屏软件解码；图片
  下载结果到达时，即使图片尺寸未改变，也清空缓存，避免旧占位图残留。
  RSS 重排/更换文章同时清空返回页缓存。多图片页不生成整页 Buffer。
- 每个活动保存下一页工作 Buffer，以及最多两张已经导入过的完整页。
  通过移动所有权保留，不再复制像素；未消费的预取页不挤掉已读页。
  总上限为 3×415872=1247616 字节 PSRAM（不含原有图片/字形缓存）。
  返回已缓存页和跳转到仍在缓存中的位置可以直接导入；首次打开、未访问
  位置和分配失败仍现场绘制，不能提前知道任意跳转目标。
- 自动翻页在整页缓存正在准备时暂停计时；重排阅读器还等待既有布局、
  字形、图片预处理阶段完成，RSS 也等待当前图片下载任务。准备失败时
  不无限等待，允许正常绘制回退。手动翻页仍可提前消费/走缓存未命中路径。

新增覆盖待设备验证：竖排批注、阅读背景、TXT 横竖排、微信划线点击、RSS
下载中翻页与下载完成更新、连续前后翻页、内存不足回退。P4 编译检查不等于
硬件刷新验证；仍应关注白膜、残影和触摸响应。

## Fast / Fastest 接入（2D 引擎）

2D 的填充、文字/图像像素写入统一保留灰度 4bit，不再因 Fast/Fastest
执行前置二值化。现场绘制与离屏预绘制使用相同的灰度量化，缓存无需按
刷新模式区分。Fast(DU) 和 Fastest(A2) 仅在 EPD 刷新任务复制出 target
之后，将更新范围按 gray<8→0、gray>=8→15 转为黑白。后续 LUT 选择与
物理状态提交都使用这份相同的 target；绘图 Buffer 不被二值化覆盖。

解除重排/TXT/RSS 的 Fast/Fastest 缓存排除条件。图片页强制 Quality、
全刷间隔、波形表、相位时序和 PSRAM 缓存数量保持不变。抖动仍未接入。
需实机验证灰色文字/抗锯齿、Fast↔Text/Quality 切换、Fastest 与连续翻页；
相较之前绘制阶段阈值248，灰色内容的黑白外观会改变，这是统一阈值的结果。

验证记录：P4 固件编译通过；从实际量化函数提取的 PC 测试通过 2856 组
矩形边界用例与 256 种双像素组合，范围外像素和行填充保持不变。
2026-10-03 用户确认本次修改实机验证成功；不代表上列所有边界场景逐项测试完成。

## 单图片合成

复用 Image 阶段的 JPG（含渐进式）、PNG、BMP 预解码灰度 4bit 数据。
Framebuffer 绘制调用明确选择离屏目标，MemoryPanel 按逻辑坐标原样复制
灰度半字节，不二次量化，不调用 M5.Display 的 native rect 接口。
单图片居中以及图文排版仍复用 draw_page_content。图片预解码失败、资源
不匹配或一页多图时，不生成整页缓存，继续原有前台绘制。
图片页及后一页 Quality 强制规则仍由原 select_page_refresh_mode 决定，
缓存命中不改变刷新模式，不改变全刷计数。

## 本地进度保存

重排阅读器不再在活动 loop 中延迟五秒保存进度；只在 Activity 析构（退出
书籍）时保存位置，与 BookReadingTimer::finish 的阅读时长保存同一生命周期。
打开设置、字体选择等暂时隐藏阅读器不会保存位置。TXT 原本即退出保存。
微信读书本地位置同样退出保存，但既有服务器阅读时长/进度定期上报保持独立。
突然掉电、复位或崩溃会丢失本次阅读期间未保存的位置与时长。
