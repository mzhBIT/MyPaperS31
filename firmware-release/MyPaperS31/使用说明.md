# MyPaperS31 离线刷机包

固件包版本：2026.11.08-11bff9c-dirty

适用设备：无名科技 Metalio-E-INK4-Plus / MyPaperS31，ESP32-S31，16 MB Flash。不适用于 MyPaperP4 或其他型号。

## 使用

1. 完整解压发布包，用电脑上的 **Chrome 或 Edge 双击打开 `刷机工具.html`**。HTML 已包含全部固件和烧录库，无需网络、Python、ESP-IDF 或本地服务器。不能在压缩包预览器、微信内置浏览器中使用。
2. 用 USB 数据线连接阅读器，关闭 VS Code/其他软件的串口监视器。网页点击「连接设备」，选择实际的 USB 串口。
3. 网页会识别 ESP32-S31、确认 16 MB Flash 并读取设备分区表。连接和预检查不会写入 Flash。
4. 选择安装方式，核对页面写入清单，点击「开始烧录」，等待写入及 MD5 校验完成。
5. 成功后尝试自动重启。若已提示校验成功但未启动，请松开 BOOT 后按 RESET 或重新上电；这种复位问题不会被误报为写入失败。

当前浏览器必须提供 Web Serial API。找不到串口时检查数据线、USB 转接器、系统驱动和串口占用。连接失败可按住 BOOT，短按 RESET，松开 BOOT，然后在网页选「已手动进入下载模式」重试。

## 三种安装方式

- **更新主系统（默认）**：只写 0x10000 的主系统。设备必须已有匹配的双固件分区表；保留 NVS 设置、模拟器和 OTA 启动选择。若当前启动选择指向模拟器，可从模拟器菜单返回主系统。
- **首次安装 / 修复安装**：写引导程序、分区表、主系统和初始 OTA 数据，默认同时安装模拟器，可取消勾选。恢复从主系统启动，不整片擦除；目标写入范围内的旧固件/旧分区数据会被覆盖。固定 NVS 区域不写入，原系统设置是否兼容取决于旧固件。
- **仅更新模拟器**：只写 0x810000 的模拟器。必须已有匹配分区表，不写主系统、引导程序、分区表或 OTA 数据。

刷机不操作 SD 卡。包内不包含个人 NVS 备份、Wi-Fi 凭据、书籍、音乐、地图、ROM 或 SD 字体。SD 卡目录和字体配置请参照项目 README；游戏 ROM 放在 `/roms/`，自行准备。

## 原始固件地址

| 文件 | 地址 | 所属范围 |
| --- | --- | --- |
| firmware/bootloader.bin | 0x2000 | 0x2000–0x7fff |
| firmware/partition-table.bin | 0x8000 | 0x8000–0x8fff |
| firmware/MyPaperS31.bin | 0x10000 | factory，8 MB |
| firmware/MyPaperEmulatorS31.bin | 0x810000 | emulator，4 MB |
| firmware/ota_data_initial.bin | 0xC10000 | otadata，8 KB；恢复默认主系统启动 |

不要将主系统镜像烧入模拟器分区，也不要把单独的主系统镜像当作地址 0 的合并固件。网页自动使用正确地址。

`manifest.json` 记录镜像身份、各文件大小、地址和 SHA-256 / MD5；`SHA256SUMS.txt` 包含发布文件的 SHA-256。HTML 自带数据，每次打开会先检查包内固件 SHA-256 / MD5，写完每个文件还会对设备 Flash 做 MD5 校验。

烧录采用官方 esptool-js 0.7.1 及其 ESP32-S31 stub。UI、离线数据、地址约束和升级流程由本项目提供；相关许可证及官方来源见 `licenses/`。HTML 是固件快照，替换外部 `.bin` 不会改变 HTML 内的固件，更新发布包应重新运行打包脚本。

## 出错

烧录中不要拔线、关闭网页或让电脑休眠。失败时网页保留错误和可导出的日志；不会把失败当作成功，也不会在写入失败后主动复位。检查连接、降低速率并进入下载模式后重试。公开包不支持已启用安全启动/Flash 加密或受限下载模式的设备，也不更改任何 eFuse。

本地打包、文件验证和浏览器流程可以自动检查；实际 USB 烧录及设备启动仍需在对应硬件上验证。
